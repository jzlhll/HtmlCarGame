# 实施阶段与验收

## 当前交付边界

当前实现阶段一与阶段二玩法，使用 Godot 4.5.1；macOS 提供本地 Universal 应用并做简单运行验证，Android 先完成共用代码、触摸与导出配置，暂不构建和设备验证。iOS、Windows 不在本次交付范围。下列清单作为设计验收要求，实际验证结论见 `../技术/运行与平台.md`。

## 阶段一：精致小场景

目标是验证美术、动画和完整游玩循环。

- 独立 Godot 工程，一块分层海底、一门可旋转炮台、一条金纹石斑。鱼捕获或离场后短暂停顿，再生成新实例。
- 六种渔网完整列表与真实不同的范围／概率组合，选中免费、发射扣对应金币和一发弹药。
- 开局 10,000 发弹药、50,000 金币，补给箱可持续补充。
- 桌面左右键转向、Shift 发射；移动端点击方向从炮口发射；不出现瞄准虚线。
- 普通鱼概率捕获、成功进鱼篓、点击出售、金币入袋、持久化与暂停。
- 完成鱼身摆动、尾鳍、受击、收网、炮口后坐和出售反馈，不能以纯色方块或未经修整的生成图充当最终效果。
- 单场景内留下鱼种与事件配置入口，但不提前制作完整名录。

阶段一的单条鱼是金纹石斑，不是基本无法捕获的巨鲨。它必须能支持反复验证捕获和出售循环。

## 阶段二：鱼群、巨鲨与金币雨

- 按名录扩展至至少十种普通鱼，加深海巨鲨与星翼宝鲂，共十二种。
- 加入小鱼群、单体、中大型鱼的混合调度，真实验证宽网的一炮多鱼。
- 巨鲨使用与普通鱼相同的概率公式，基础概率极低，全鱼种均无累计必捕，成功后手动出售。
- 星翼宝鲂以东方飞角鱼为原型，偶尔展翼经过，提前 3 秒预警，有效渔网实际覆盖时必触发连续金币喷发，金币飞入金币袋。
- 全部事件接入暂停、存档与对象复用，避免只做一段脱离结算的演示动画。

## 阶段三：macOS 与 Android 交付

- 固定 Godot 稳定版本和匹配导出模板，整理各平台配置、图标、应用标识、资源许可及操作说明。
- 验证 macOS 键盘逻辑、窗口适配和失焦；Android 实现安全区、触摸和后台恢复入口，设备验证留待后续。
- 按实际获得的授权与仓库规则执行各平台验证。当前规则禁止主动运行 Gradle 和 iOS 构建／安装验证，这些平台的相应验证由用户或后续获授权流程完成。
- 提供平台验证矩阵：已运行设备与系统、画质、分辨率、检查内容、失败与未验证项。不能将“配置了导出预设”标记为“四端通过”。

## 人工验收清单

### 操作与界面

- 桌面移动或点击鼠标不会改变炮管或开炮；左右键方向正确，同时按下不转动；任一 Shift 可发射，双 Shift 不翻倍。
- 桌面按住 Shift 连发受统一射速限制，失焦、暂停、弹层关闭后不会自动补射。
- 手机点击有效水面时炮弹确实从炮口出发，方向正确；点 UI、多指、冷却期点击不额外扣费。
- 六档渔网均可发现、可切换；从破网到龙绡网品质递增，界面无概率、半径数值、虚线和范围预览。
- 不同画幅下炮台、鱼篓、渔网列表与金币袋均可使用，中文不截断。

### 捕获与经济

- 每发只扣一次弹药与金币，资源不足不扣费；在途炮弹保持发射时所选渔网。
- 一张网覆盖多鱼时逐鱼独立判定，特效持续帧不会重复抽取；相邻炮弹不会重复捕获同一已完成实例。
- 相同渔网下普通鱼与鲨鱼的概率按标准体型递减；多次未捕获不增加下一次概率，不存在累计必捕。
- 巨鲨概率极低但不为零；Bonus 被有效网覆盖时必捕。炮弹被其他鱼挡住且网范围不足时不能触发 Bonus。
- 捕获普通鱼后余额不自动增加；点击出售后鱼篓数量与金币同步变化；连续点击不重复卖出。
- 重启不会重复发开局资源；补给与出售记录可恢复。

### Bonus

- 鱼篓打开时海面持续运行，普通鱼和在途炮弹继续活动，不能通过出售面板暂停鱼群。
- 鱼篓在 Bonus 预警开始前打开：到期事件延后，关闭后才出现完整 3 秒预警，不立即刷鱼。
- 预警开始后打开鱼篓：倒计时照常到零并刷新 Bonus；已出现的 Bonus 不冻结，不因鱼篓开关延长停留。
- 反复开关鱼篓不会重置已开始的预警；暂停／后台则冻结剩余时间，恢复和读档不重置倒计时。
- 预警保持可见，不被鱼篓遮挡；倒计时边界和鱼篓开关同帧时行为符合输入优先规则。
- 星翼宝鲂只偶尔经过，在可射区域停留合理时间，与普通鱼有明显轮廓区别。
- 命中后连续多批金币弹出并汇入袋口，最后总增量等于内部奖励配置。
- 同一鱼被多网命中、特效重复回调、切后台或恢复存档均不会再发一笔奖励。
- 低画质减少粒子但不减少奖励，减少闪光模式仍保留完整多批节奏。

### 美术与性能

- 鱼头稳、鱼尾摆、胸鳍轻动，转弯自然；炮台旋转轴和出弹点正确。
- 海底、鱼与炮台的光照和视角统一，透明边缘无白边，网和金币不遮挡操作。
- 记录普通场面、鱼群密集、巨鲨与金币雨场面的帧耗时和内存；以实测结果调整预算。
- 持续游玩后离场对象与特效正常回收，内存不持续无界增长；保存过程不造成明显连发卡顿。

## 开发开始前需要落实的事项

- 记录 Godot 具体稳定版本与导出模板版本。
- 选定可用于性能评估的目标手机与桌面设备；未提供设备时先明确验证范围，不承诺帧率。
- 为正式生成和第三方资源建立素材清单与许可记录。
- 确认首阶段以金纹石斑展示品质，完整鱼种与 Bonus 按阶段二进入可玩版本，避免将阶段一误当作完整游戏。
