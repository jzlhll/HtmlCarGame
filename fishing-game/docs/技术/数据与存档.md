# 数据与存档

## 配置资源

当前使用 Resource 脚本与 `.tres` 定义鱼、渔网与事件；编队参数由 FishDefinition 和 SpawnDirector 管理，SchoolDefinition 留作独立编队资源扩展边界。

| 定义 | 必要字段 |
| --- | --- |
| NetDefinition | `id`、`tier`、`display_name`、`icon`、`mesh_texture`、`coin_cost`、`ammo_cost`、`radius`、`probability_factor`、`effect_theme` |
| FishDefinition | `id`、`display_name`、`reward_mode`、`p_base`、`sale_value`、尺寸、碰撞形状、速度区间、动画与资源引用 |
| SchoolDefinition | `id`、成员鱼种、数量区间、队形、成员偏移、路径与相位配置 |
| EventDefinition | `id`、间隔区间、停留时长、同时数量、入场与奖励表现、固定奖励 |

`reward_mode` 仅设 `inventory` 和 `bonus_direct`：普通鱼与鲨鱼统一概率捕获后入鱼篓，Bonus 实际覆盖即必捕并直接发奖。普通鱼与鲨鱼不保存或使用累计必捕状态。渔网内部参数不能直接绑定 UI，界面只读取允许展示的字段。

## 运行状态

| 对象 | 状态 |
| --- | --- |
| GameSession | `playing`、`paused`、`saving_error` |
| 普通鱼／鲨鱼 | `entering` → `swimming` → `captured` 或 `escaping` → `removed` |
| Bonus 鱼 | `entering` → `swimming` → `rewarding` → `removed`，或 `escaping` → `removed` |
| Bonus 调度 | `waiting` → `warning`（3 秒）→ `active` → `rewarding`／离场 → `waiting` |
| 炮弹 | `flying` → `net_resolved` → `recycled` |
| 渔获条目 | `available` → 从鱼篓删除并计入一次出售交易 |

鱼实例具有稳定 `fish_instance_id`；炮弹具有稳定 `shot_id`；这些标识服务实体识别、存档和结算去重，不用于堆叠额外异步版本机制。张网记录本次已处理实例集合，离场后按生命周期回收。

`captured`、`rewarding` 在结果提交后不可重新接受命中。动画回调只负责表现回收。玩家点击出售时，以当前真实库存数量核算，不能相信过时按钮上的数字。

## 存档内容

- `schema_version`：数据格式版本。
- `initialized`：是否已发放新档资源，防止重启重复发开局礼包。
- `wallet`：金币与弹药，均为非负整数。
- `inventory`：捕获实例／批次、鱼种、数量、捕获时出售单价与唯一标识。
- `selected_net_id`：当前选择，缺失配置时回退到破网（`net_qingxi`）。
- `settings`：声音、减少闪光与画质。
- `session_snapshot`：场内鱼的 ID、种类、路径进度；在途炮弹的 ID、已冻结网配置、位置、方向及剩余寿命；刷新与事件剩余时间、Bonus 调度状态及预警剩余时间；游戏随机状态。
- `statistics`：累计捕获、出售与事件次数，只作本地展示，不公开隐藏效果参数。

保存会话快照使重启后能继续已消耗弹药的射击与鱼的游动，不通过重新进入重复获得首场 Bonus。待判定随机状态随快照恢复，避免重启提供免费重新抽取结果。

## 交易边界

- 发射：扣金币、扣弹药、登记炮弹是一次状态变更。
- 普通捕获：鱼不可再捕获、加入鱼篓、记录本次网结果是一次状态变更。
- 群体捕获：同一张网的全部目标结果作为一批提交，避免逐鱼大量写盘。
- 出售：减少／删除渔获与增加金币是一次状态变更。
- 补给：金币与弹药同时增加是一次状态变更。
- Bonus：鱼进入 `rewarding` 与增加整笔奖励是一次状态变更。

所有交易经 EconomyService 单一入口串行处理，GameSession 在每个发生交易的物理步结束后，把同一步内结果合并为完整快照并同步提交；普通运动每两秒保存。UI 交易、切后台和正常退出立即提交。当前不引入异步保存队列，避免多份状态乱序回写；未完成持久化的状态不提示“已保存”。

普通捕获、出售、补给及 Bonus 奖励，在保存确认后才发布成功信号和庆祝效果。发射可先表现，但保存失败必须暂停后续操作并保留待保存快照供重试，不静默继续消耗。进程突然终止可能丢失尚未落盘的最后一批运动或射击；恢复必须整份回到最近一致快照，不出现“只扣钱不留炮弹”或“发奖两次”。

## 写入与恢复

1. 写入同一 `user://` 目录中的临时存档。
2. 完成写入并校验结构、数值范围和必要引用。
3. 保留上一份有效存档为备份，再替换正式存档；实际替换行为需要按平台验证，不假定所有平台具有同样原子性。
4. 启动优先读取有效正式档；正式档异常时尝试备份并提示恢复情况。
5. 正式档和备份均失效时保留损坏文件，提示用户选择重试或明确新建存档，不自动覆盖。

缺少文件可以建立新档；读写错误、版本过新或解析失败不能当作“没有存档”。迁移按 `schema_version` 顺序进行，并保留迁移前备份。资源配置更新不得追溯降低鱼篓已有出售单价。

## 暂停与视觉恢复

- 鱼篓开关是独立 UI 状态，不将 GameSession 切换为 `paused`；打开时停止新发射但在途炮弹继续。只在 Bonus 的 `waiting` 阶段阻止开始预警，`warning`／`active` 阶段继续运行。
- 恢复存档按已保存的 Bonus 调度状态和剩余时间继续，不把已启动的预警退回等待状态。
- 暂停时冻结模拟和事件时间，清空 Shift／转向／触摸按住状态；恢复不补发炮弹。
- 退出前提交可恢复的快照；应用进入后台先停止接受新输入再请求保存。
- 已提交的 Bonus 奖励不依赖金币粒子完成。恢复时展示真实余额，已发奖的鱼直接完成退出表现或移除，不能再次变回可奖励状态。
- UI 展示余额在动画期间可缓动，但消费检查始终读取真实钱包；新交易出现时更新展示终点，不在结束回调覆盖成旧余额。
- 屏幕尺寸变化只重新计算 UI 和特效终点，不重建经济状态。
