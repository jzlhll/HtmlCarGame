# 技术架构

## 技术选择

| 范畴 | 选择 | 原因与约束 |
| --- | --- | --- |
| 游戏引擎 | Godot 4 稳定版 | 原生支持四个目标平台；MIT 许可，可闭源商用 |
| 逻辑语言 | 类型化 GDScript | 与场景、资源、信号和编辑器集成；首版不混入 C# 或自编译 C++ |
| 场景 | 原生 2D，使用分层美术制造纵深 | 保持鱼群可辨识与移动端性能，支持精细动画 |
| 渲染 | 优先评估 Compatibility | 作为 2D 与较广硬件覆盖的起点；以目标设备表现决定是否采用 Mobile |
| 动画 | AnimationPlayer、Tween、Polygon2D／Skeleton2D | 帧动画、局部骨骼与网格变形结合，避免整张图平移 |
| 材质 | CanvasItem Shader | 水下光纹、鱼体摆动、受击、网绳与渐变光效 |
| 特效 | Godot 粒子及对象复用 | 炮口、气泡、捕获、金币雨按预算控制 |
| UI | Control、Container、Theme | 键盘／鼠标菜单和触屏共用布局结构与主题 |
| 配置 | 自定义 Resource，保存为 `.tres` | 配置可检查、可调参；运行状态和配置分离 |
| 存档 | 本地带版本的 JSON | 单机钱包、渔获、设置与事件恢复，无服务端依赖 |
| 音频 | AudioStreamPlayer 与音频总线 | 原创或许可明确的短音效，控制并发与音量 |

当前固定 Godot 4.5.1.stable.official.f62fdbde1，使用同版本官方导出模板，无第三方插件。当前落地 macOS 与 Android，iOS、Windows 仅保留共享代码可复用性，具体交付与验证见 `运行与平台.md`。

Godot 许可要求保留版权与许可说明，游戏源码无须公开；第三方插件、字体、音乐与素材的许可独立处理。[官方许可](https://godotengine.org/license/)

官方参考：[平台与语言](https://docs.godotengine.org/en/stable/about/faq.html)、[渲染器选择](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html)、[iOS 导出](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_ios.html)。iOS 导出需要 macOS 与 Xcode，不能将跨平台引擎理解为省略签名和平台发布流程。

## 工程目录

工程采用以下自包含布局。

```text
fishing-game/
  AGENTS.md
  README.md
  docs/规划/
  docs/技术/
  project.godot
  scenes/             # 游戏场景、实体和界面
  scripts/core/       # 模拟时钟、状态、输入
  scripts/gameplay/   # 炮台、鱼、渔网和刷新
  scripts/economy/    # 钱包、鱼篓和结算
  scripts/ui/         # 界面与表现桥接
  resources/fish/
  resources/nets/
  resources/events/
  assets/art/
  assets/audio/
  assets/fonts/
  shaders/
  exports/            # 导出产物，不提交仓库
```

`.godot/`、导出物、临时预览和本地工具缓存写入本工程的忽略规则。正式资源必须归属本工程，不能引用生成工具的全局缓存路径。根目录和其他游戏的配置不承担本工程功能。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| GameSession | 游戏状态、共享时钟、暂停及持有本次会话模块 |
| InputRouter | 按平台转换输入；桌面只接受方向键与 Shift，移动端处理点击方向 |
| CannonController | 转向、角度限制、射速、发射请求和炮管表现 |
| ShotSystem | 固定每发配置、弹道推进、首次碰撞及张网触发 |
| CaptureResolver | 收集命中目标、每鱼一次判定、普通鱼／鲨鱼概率判定及 Bonus 有效覆盖必捕 |
| FishActor | 单条鱼的运动、受击表现和有效状态；不直接发金币 |
| SpawnDirector | 鱼群与单体、巨鲨和 Bonus 的时序及数量预算，包含 3 秒预警与鱼篓刷新门控 |
| EconomyService | 资源开销、补给、鱼篓变更、出售和 Bonus 奖励的唯一写入口 |
| SaveRepository | 读写、校验、备份、迁移和恢复；返回明确成功或失败 |
| EffectsDirector | 将已经确认的玩法事件映射到粒子、动画、音效与视觉余额 |
| HudController | 钱包、弹药、六网列表、鱼篓与菜单；不运行概率计算 |

优先通过场景组合与显式引用持有模块，不为每个模块建立 Autoload。配置资源只读共享，实例状态独立。UI 订阅已经提交的变更信号；实例释放时断开临时连接并停止 Tween。

## 模拟与结算时序

- 使用固定物理步推进鱼和炮弹，显示帧用于插值与动画。默认物理步 60 Hz。
- 高速炮弹采用前后位置线段／扫掠判定，避免低帧率穿鱼；网覆盖与鱼体简化碰撞形状相交。
- 不为鱼群启用完整刚体堆叠。路径和编队负责游动，碰撞只服务命中。
- 鱼篓可见性与 GameSession 暂停状态分离：鱼篓打开只截获操作输入并门控尚未启动的 Bonus 预警，不冻结世界。预警开始前检查并预留事件容量，开始后不受鱼篓影响。
- 输入先通过 UI 消费和会话状态过滤，再请求发射；每帧最多根据射速预算补有限发数，长卡顿不能瞬间补出大量炮弹。
- 发射和捕获由主线程按固定顺序处理。金币雨视觉状态不能回写钱包。
- 保存失败进入可恢复的错误状态，暂停新交易并提供重试，不继续展示已获得但无法保存的奖励。

## 平台适配

- 世界采用 1600×900 基准坐标，宽高比例通过视口适配；输入统一映射到世界坐标，屏幕分辨率不能改变网的覆盖。
- 横屏优先；超宽屏使用安全的视口扩展或边饰，不改变可捕获区域的公平性。不同尺寸不裁切炮台和金币袋。
- Android/iOS 处理触摸、安全区与切后台；Windows/macOS 处理窗口大小、键盘输入和失焦暂停。
- 设置和存档写入独立 `user://` 应用目录，与其他游戏隔离。采用平台默认字体回退前，先验证中文覆盖；正式发布优先打包许可明确的中文字体。
- 原生发布需要各自工具链、签名和设备验证。macOS 已有本地 Universal 应用；Android 当前只实现共用玩法、触摸与预设，暂不构建及设备验证；不创建 iOS、Windows 导出预设。

## 性能基线

- 首个场景以目标手机稳定 60 FPS 为目标，16.7 ms 是帧预算而非保证；进入实现后记录设备型号、分辨率、引擎与画质。
- 完整场景首轮上限：60 条鱼、24 枚在途炮弹、12 张表现中的网、64 枚主金币、300 个环境／捕获小粒子。
- 图集按海域和用途组织，避免重复纹理；长边优先控制在 2048，场景背景按实际分辨率评估，不能给每条小鱼使用 4K 图。
- 绘制次序固定，限制全屏透明层和动态灯光。光纹使用低成本 Shader，避免多个全屏模糊堆叠。
- 高频生成实体复用对象，离场回收前重置状态、材质参数、计时器与信号；只有测量确认热点后才引入更复杂的批处理。
- 降低画质优先减少光效、金币与环境粒子、渲染分辨率，不改变鱼数、鱼种、射速、判定次数、奖励或事件时钟。

## 扩展边界

后续海域、炮台外观与新鱼种通过资源配置扩展。账户、联机、支付、广告和远程配置不属于当前架构实现范围；不为这些假设提前搭建服务端。
