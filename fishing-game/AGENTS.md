# fishing-game 开发规则

## 文档入口与范围

- 阅读 `docs/README.md`，按任务阅读 `docs/规划/` 与 `docs/技术/` 下对应文档。
- 当前实现阶段一与阶段二玩法；当前交付平台为 macOS 和 Android，iOS、Windows 仅保留共享代码可复用性。
- 文档描述目标设计，不代表功能已经实现；数值是首轮调参基线，不能描述成实测结论。
- 使用 Godot 4.5.1 稳定版与同版本官方导出模板，不擅自升级引擎；macOS 可以做简单运行验证，Android 暂不构建或设备测试。

## 协作隔离

- 本任务文件限定在 `fishing-game/` 内；不要修改仓库根目录文档、依赖、脚本、CI 或其他工程。
- 共享仓库中另有会话工作，不切换分支、不重置工作区、不清理未知文件、不操作其他任务的暂存内容。
- 文档与后续游戏工程自包含；不得依赖其他游戏的启动服务或可变资源目录。
- 遵循上级规则：中文回复和代码注释、英文日志；不主动生成测试，不运行 Gradle；iOS 修改不进行构建或安装验证。

## 技术约定

- 采用 Godot 4 稳定版、类型化 GDScript、原生 2D 场景和 2.5D 美术。实施前固定具体稳定版本及对应导出模板。
- 使用 Godot 内置动画、粒子、音频和 Shader；不默认引入 Three.js、WebView、商业骨骼动画运行库或联网服务。
- 捕获判定、钱包和渔获结算集中管理；动画、粒子和界面不能直接修改奖励。
- 金币与弹药使用整数；渔网配置在发射时固定，切换渔网不能改变已经飞行的炮弹。
- 使用现有状态机、生命周期和明确的等待关系处理异步回写，不无故增加 revision/generation 状态。
- 普通鱼与大鲨鱼统一按概率捕获，同一渔网下体型越大基础捕获率越低，不设累计必捕。Bonus 鱼是例外：实际被有效渔网覆盖时必捕，不能穿过其他鱼或超出网范围触发。
- 概率和范围是内部配置。六档渔网从破网逐步升级到龙绡网，界面展示档位、名称、真实网具图标、每发金币价格和选中状态，不展示概率或半径数值；全部直接可选。
- Windows/macOS 使用左右方向键转炮、Shift 开炮；不提供鼠标瞄准和虚线轨迹。Android/iOS 点击水面方向从炮口发射。

- 鱼篓打开不暂停海面；Bonus 预警持续 3 秒，只有鱼篓关闭时才可开始预警。预警一旦开始，打开鱼篓也不取消预警或阻止入场，已入场 Bonus 正常游动离场。

## 资源与验证

- 自制和生成素材需要记录来源、生成提示词、工具、许可及加工方式；第三方素材另行核查授权。
- 性能优化以目标设备实测为依据，限制透明叠加、纹理尺寸、粒子与音频并发。
- 后续开发按 `docs/规划/实施阶段与验收.md` 完成人工验证；未验证的平台明确标记，不将导出支持等同于四端已交付。
- 新增机制时同步修改对应权威文档，只保留当前设计结论。
