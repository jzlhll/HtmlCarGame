# 得分与本地存档

[返回总览](../README.md) · [游戏状态](01-gameplay.md) · [车辆速度](02-vehicles.md)

## 计分

只按实际沿道路前进的距离计分：`distanceMeters += speedMetersPerSecond × deltaSeconds`，`score = floor(distanceMeters)`。一米一分，不添加吞吃、升级、季节或连击加分。

距离使用道路中心线的前进弧长，横向移动不增加路程，弯道不能用模型投影的直线位移计分。距离内部保留小数，显示不足一公里时为整数米，达到一公里后可显示两位小数公里；分数始终是整数。

仅 `RUNNING` 累计距离。速度为零不加分，暂停、准备、死亡动画与结算均不加分。碰撞逻辑需要推进到首次致命接触时刻后锁定距离，不能把剩余逻辑步的路程加到已死亡玩家身上。

## 结算与记录

每局结算展示分数、精确距离、有效行驶时间、最高等级、六类车吞吃数、结束原因和是否刷新最佳成绩。有效行驶时间包含速度为零但仍在行驶状态的时间，不包含暂停。

初版保存最近 20 局、最佳成绩及排行榜前 10 局。主动结束同样是已完成局，记录 `quit` 并参与排名；死亡记录 `death` 和具体碰撞原因。页面关闭、刷新导致未结算的局不追加成绩。

排名先按分数降序；分数相同时按实际距离降序，再按结束时间由早到晚。等级、吞吃数与用时用于展示，不改变以路程为目标的排名规则。最佳记录保存完整对局数据，不能因它离开“最近 20 局”而丢失。

## localStorage 方案

localStorage 适合少量成绩和偏好，数据可跨浏览器会话保留，按来源隔离。直接 `file://` 打开页面时的行为没有可靠保证，因此初版固定使用本机 HTTP 地址，例如 `http://localhost:5173`，并固定协议、主机与端口。参见 [MDN：localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)。

通过项目中的本机启动入口提供页面、Three.js 与素材，不依赖线上 CDN。Three.js 官方也建议本地开发通过本机服务器访问，参见 [Three.js 安装说明](https://threejs.org/manual/pages/installation.html)。具体启动工具在实施阶段确定，不在设计阶段安装依赖。

存档只在当前浏览器和来源有效；更换浏览器、改端口或把 `localhost` 换成 `127.0.0.1` 都不会自动共享。清理网站数据会删除记录，隐私模式记录通常在隐私会话结束后清除。初版不提供云同步或续局。

## 数据结构

使用单一命名键 `htmlCarGame.save.v1`，一个 JSON 文档保存关联数据，避免多键更新时成绩和统计不同步。

| 字段 | 内容 |
| --- | --- |
| `schemaVersion` | 数据结构版本，初版为 1 |
| `rulesVersion` | 当前计分、车型、碰撞与关键平衡规则版本，初版为 1 |
| `updatedAt` | 最近保存时间，ISO 8601 |
| `settings` | 简化效果、音量等用户偏好 |
| `bestRun` | 当前规则版本的最佳完整记录，初始为 `null` |
| `recentRuns` | 最近 20 局记录 |
| `leaderboard` | 当前规则版本前 10 局记录 |
| `stats` | 已结算总局数、总距离、累计吞吃数量 |

每局记录包含 `runId`、`runSeed`、`rulesVersion`、`endedAt`、`endReason`、`deathCause`、`distanceMeters`、`score`、`activeSeconds`、`highestRank`、`eatenByType`。`deathCause` 在主动结束时为 `null`。同一 `runId` 只接受一次结算。

结构版本用于迁移字段，规则版本用于区分可比较的成绩；改变积分或影响难度的核心参数时提升规则版本，排行榜与最佳成绩只比较当前规则版本，旧最近记录保留版本标签。

## 读取、写入与失败

启动读取时，将获取 localStorage、读取键、解析 JSON 都放在异常处理内。校验版本、数组数量、字段类型、合法等级、非负有限距离和分数；分数按校验后的距离重新计算，不信任原值。

坏数据使用内存默认值继续游戏，并提示“历史记录暂不可用”；能读取的损坏原始字符串保留在内存中供导出，不立即覆盖旧键。只有成功解析、完成迁移后才自动保存正常记录；损坏/未知版本状态下，需要用户明确重置记录才能重建该键。遇到未来版本时保持原数据，只使用内存记录。

结算时先更新内存中的最佳、最近记录、排行榜和统计，再一次写入完整 JSON。写入被浏览器策略禁用或空间不足时，本局结果仍正常展示，并提示“本次成绩仅在当前页面保留”。后续结算可重试，不能因持久化失败中断游戏。

localStorage 操作是同步的，因此不在每帧写入，只在有效结算或偏好变更时保存。参见 [MDN：Web Storage API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API)。不使用 `localStorage.clear()`，重置时只删除本项目的键。

初版以单个游戏标签页为记录写入者。启动时可监听同来源存档变化，在待机/暂停时提示其他标签页有新记录并重新读取；不承诺多个标签页同时结算时零丢失，需多人并发存档时再引入专门存储方案。

本地排行榜不做防作弊保证；开发者工具可以修改 localStorage。后续可增加记录导出/导入与主动清除入口，清除操作需要针对性确认，但不是首版核心依赖。
