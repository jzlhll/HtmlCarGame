# 开发与验证原则

操作以 [通用验证流程](validation.md) 为准。

| 原则 | 执行方式 |
| --- | --- |
| 按实际风险验证 | 接弹、时序与学习记录检查交叉边界，局部改动只检查受影响结果 |
| 复用有效信息 | 独立查询批量执行，依赖查询顺序展开；新改动、失败或疑点才触发重查 |
| 先测量后优化 | 固定场景与条件区分 CPU、GPU、像素和准备阶段，局部计数不承诺整局帧率 |
| 保持资源边界 | 模型和纹理只在非游玩阶段生成，优先缓存、共享几何、实例化和有界池 |
| 完整处理异步结束 | 复用任务取消、状态校验和结构化等待，必要任务失败后等待其余任务停止 |
| 集中预览 | 先确认逻辑和资源边界，再统一核对代表画面；故障先查服务和资源 |
| 复用音效能力 | 统一使用 `audio.js` 的 Web Audio 合成，数值集中 `config.js` 的 `AUDIO` |
| 保持文档聚焦 | 只维护最终规则、实现和必要兼容说明；赛车资料参考 `main` 分支 |
