## 范围与方式

日常开发按[自测策略与并发协作](../../AGENTS.md#自测策略与并发协作)选择最小验证；下面的契约矩阵是定位受影响项的索引，不是每次修改必须全量执行的清单。参数／文案微调以静态核对为主，局部问题直接进入对应状态；仅在实际风险、失败证据或发布要求下扩展范围。

复杂开发先拆成稳定批次，允许主agent开发下一独立模块、只读子agent验证前一模块。结果须标明代码状态，相关文件变化后旧结果不能作为当前通过依据；集成时只补共享接口和交互路径，不重复模块检查。浏览器／GPU计时与同一缓存写入保持串行，避免并行争用污染结果。

不主动新增测试框架或仓库内测试文件，优先复用已有函数、脚本、降落调试、服务与页面；必要临时场景放在仓库外并及时回收本次服务与页面，保留用户已有状态。普通提交不重新要求全量浏览器、打包、性能或三关验收。

逻辑检查与浏览器确认分开记录。Node采样不能代替浏览器准备时间；绘制提交和CPU提交耗时不能当作GPU执行时间或帧率承诺。没有实际试听时，不把音色标记为新验收结果。下方数值证据仅适用于注明的资源配方和检查范围，不能因文档参数更新就宣称重新完成了测量。
