# 通用验证流程

[返回实现入口](README.md)

## 浏览器端口与服务检查

缺依赖时执行 `npm ci`。预览前检查本机端口及服务归属；启动时显式指定空闲 `PORT`，等待服务输出成功地址，再通过 HTTP 打开页面。不要停止用户原有服务，不直接打开 HTML 文件。浏览器连接失败时先查服务是否仍运行、端口和资源状态，不反复刷新掩盖错误。

优先使用当前可用的浏览器工具完成交互与画面核对。仅复用已确认可用的环境，不为局部改动新增验证框架或持久测试文件。

## 选择受影响范围

按 [英语空战验收](english-air-combat-validation.md) 选择本轮范围：输入与题型核对接弹、状态和单次记录；账号与学习数据核对隔离、异步保存及恢复；时间逻辑核对固定步、暂停、失焦和截止边界；资源与渲染核对生成、缓存命中、预热和画面。

不因普通文案或样式调整重跑整局。已有有效结论只在新改动、失败或未解决疑点影响它时重新检查。源码或计划只读分析不改文件，不主动新增测试文件，不运行 Gradle。

## 资源与性能

固定种子、视口、DPR、画质、密集场景及缓存条件后对照；首屏加载、资源恢复／生成、场景构造、GPU 预热分别计时。rAF 帧间隔、CPU 提交耗时和异步 GPU 计时分别报告，不把几何／调用／像素降幅换算为 FPS 收益。

核对首次生成、持久缓存命中、同页复用、无 Worker 及存储不可用路径。并行任务全部完成或停止后才开放操作，失败先等其余任务结束，再关闭数据库连接和展示重试；失败不得清理旧可用资源或登记持久成功。

涉及几何与纹理时确认游玩不生成资源，预热覆盖所有几何和材质变体；尺寸／DPR／画质变化同步画布、相机及点径，题面文字保持清晰。发布整理后检查子路径、模块及预加载地址、Worker 依赖和实际体积，完整静态文件小于 10 MB。

## 交付

`git diff` 及其变体直接执行原生命令。检查本地文档链接和修改范围，移除临时入口、缓存与预制产物。仅报告交付结果、实际失败和影响结论的验证缺口，不逐项罗列常规检查或省略的构建。程序版本、包版本和正式 tag 的约定见 [版本与资源升级](resource-upgrade.md)。
