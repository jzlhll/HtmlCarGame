# 技术与实施说明

[返回总览](../README.md)

## 技术与本机开发

原生 JavaScript ES Modules、Three.js `0.186.1`、DOM／CSS／SVG 界面与 Web Audio 合成音效、本地 Speech Synthesis 英文播报，无编译或打包步骤。入口为 `index.html`，import map 从本机依赖目录加载 Three.js 与 BufferGeometryUtils；运行不依赖 CDN。

依赖缺失时执行 `npm ci`，随后 `npm start`，地址为 [http://localhost:5186](http://localhost:5186)。多工作目录可用 `PORT=5187 npm start` 选择空闲端口，不停止用户已有服务。`scripts/serve.mjs` 只监听回环地址并限制资源根目录，通过 HTTP 加载，不直接打开 HTML。

保留现有 macOS 启动脚本与 Release 资源整理工具；当前不发布飞行分支。增加资源或 addons 时同步维护服务白名单和发布拷贝清单。

## 状态与时钟契约

主要流程为 `READY → INTRO → STARTUP → TAKEOFF_ROLL → INITIAL_CLIMB → CRUISE → APPROACH → LANDING_ROLL → TAXI → COMPLETE → RESULT`；实体损毁独立经过`CRASH → RESULT`。满足进近空间条件时也可从爬升直接进入 APPROACH；没有达到初始爬升目标不会阻止玩家尝试安全着陆。安全接地是 LANDING_ROLL 的唯一入口；任务胜利还必须在圈内停稳。

准备、四秒开场与三秒启动不消耗航程时限。首次 R 合法放行调用 Mission.start，此后即使刹停、重新驻车或恢复准备，本关时限仍继续；只有重开清空。所有物理、遭遇、收放、提示、停机保持和任务时限都由有效游戏步推进，暂停／失焦冻结，恢复不补算停留时间。

Game 优先处理飞行接地／越界与世界／交通碰撞失败，再处理任务完成。本关时限之外不接受停机胜利。完成冻结飞机，1.5 秒短反馈后进入静止结果页；失败只结算一次。结果用时为任务时钟而不是准备耗时。

滑跑、爬升、巡航、进近和着陆之间保留持续操纵；暂停、结果、重开及准备／放行等输入门控切换清理按住集合。普通开关和受阻指令不重置逻辑步余量。

## 飞行与世界数据

内部采用米／秒／弧度，Three.js Y 向上，计划航线沿 −Z。`aircraft.position` 与轮子、机腹、翼尖接触点使用同一参考点；高度表显示最低接触点离地高度 AGL，导航显示海拔 MSL，限高检查 MSL。固定质量存于 AERODYNAMICS，不引入载重或机场性能表单。

平移使用推力、升力、阻力与重力三维积分，T／S 通过固定步有限施力控制纵向变速，点按不直接缩放速度，仅T请求内按W档位计算推进力，请求结束推力归零、不保速，提速受推力上限约束，发动机声音平滑跟随。迎角由俯仰减航迹角得到，临界后升力连续衰减、分离阻力上升；恢复有安全区保持时间。操纵效能受动压和失速影响，俯仰／滚转变化率受限；不直接跟随目标高度或垂直速度，点按额度的渐进施力属于明确玩家请求，不采用完整刚体力矩／侧滑／结构损伤模型。

G／W 的 EXTENDING／RETRACTING 进度驱动视觉和受力。flaps／flapsPosition 保留内部标识，CLEAN／0 为减速板关闭，TAKEOFF／1 为打开。W 无高度或速度门槛，起飞完全关闭，安全接地完全打开；G 保留收轮高度和放轮速度限制。接地后自动减升增阻，S 直接减速并显示轮刹反馈。`Flight.landingStatus()`统一接地判定、角度指引与预览机身三档安全颜色；预览仅修改既有蒙皮材质颜色，保留纹理，不生成新模型／纹理或影响主场景涂装。安全接地后`landingAlignment`按固定步在1.2秒内平稳归正，暂停冻结、重开重置；最低接触点贴合当前机场标高，不平移到跑道中心，不替代玩家滑行停机。姿态／机轮小视口尺寸变化由同一ResizeObserver刷新裁剪区域。

每个关卡页面创建一次RouteWorld并复用，重开不重建静态场景；通过 ?level=1／2／3 选择关卡，原生页面导航结束旧页面和声音，不在运行中改写全局配置。createRoute生成独立规则与机场数据，terrainElevation是共用地面标高的唯一来源。建筑／地标用包络和空间网格索引，山体以固定高度网格直接定位对应三角形并线性插值查高，近景绘制使用同一网格，远景索引简化不改写碰撞；飞机多个带半径采样点扫过前后位置，每个固定步只计算一次前后姿态的采样端点，世界与交通碰撞共用。整体扫掠包围盒先排除不可能接触的建筑、山体和交通目标，再保留原有逐点窄相检查及山面采样间距；不得通过降低物理频率或扩大穿透容差提速。交通碰撞使用双方相对位置线段，飞鸟逐只检查，固定队形偏移随航向缓存。详细边界和着陆阈值见[航程专题](../design/07-航线与关卡.md)。

## 渲染、导航与事件

完整前窗使用主场景／主相机，固定飞行员眼位向下 5°保留地景；机外姿态使用同一显示姿态与独立裁剪视口，不新增 WebGL 上下文。开场以有效时间采样平滑轨迹，外壳和内舱渐变保留深度写入；对数深度、表面 polygonOffset、36 km 远裁剪及 32 km 天空球控制远近景闪烁。阴影只在可见机体、收放、机壳透明度或 WebGL 恢复时失效；山谷遮蔽在建图时烘焙为顶点数据，不每帧扩大阴影范围。

首屏直接展示标题、可点击开始入口与轻量客机预览，完整场景在随后等待窗口准备；点击开始时若必需资源尚未就绪，显示真实进度，完成后立即进入原有四秒运镜。进入运镜前异步预编译主场景与姿态卡片材质、预上传基础纹理，并用小视口提交全部细节级别的几何，随后恢复可见性、裁剪状态与机场阴影。加载不消耗游戏时钟。

逻辑快照按帧余量插值，暂停／结果保留最后显示姿态。机场与地景的静态变换矩阵在创建时确定，后续仅更新可见性和纹理偏移；新增会移动的地景必须恢复相应节点的矩阵更新。飞机按材质合并静态几何，并保留轮、减速板和航行灯的独立控制；飞机合批保留材质需要的UV属性，蒙皮与金属共享纹理和生成结果。机场在各自局部坐标中按材质与阴影属性合并不透明标线和建筑，透明编号保留独立排序；其他静态地标按640米空间单元合批，山体细节与实例森林保持独立。驾驶舱17块面板与框体按三种材质实例化，尺寸变化时统一更新实例矩阵。建筑实例化；山体共享网格顶点、法线及颜色，通过不同索引切换远近细节，森林按区块切换实体树冠／交叉树片并裁剪；瀑布只更新纹理偏移，交通模型预先建立，读取逻辑对象位置。当前地图有限，不声明已实现无限巡航或地形回收。

航线轨迹每 0.25 秒记录真实世界位置，包含偏航；导航和雷达以 8 Hz 更新 SVG，固定网格与计划线只创建一次，实际轨迹只格式化新增采样，目标节点按稳定 ID 复用，重开清空轨迹和目标。仪表复用文字节点，仅写入变化的字段；同一帧的多个状态通知合并为一次界面刷新，输入门控和音频静音仍即时执行。雷达目标、箭头与场景模型使用同一位置／速度／航向，前 10 秒预告闪烁，危险依据最近接近距离与高度差，暂停不闪烁、不移动。A 关闭雷达时不显示目标。

临时提示以有效事件 ID 去重，最多 2.5 秒，不由速度／高度刷新计时。安全区恢复后才允许新的危险进入事件；失速与超高故障优先于交通／姿态，后者优先于普通操作。每道瀑布按独立ID每局只奖励一次。常驻仪表、任务与故障状态不使用短提示生命周期。

舱门内部 `systems.door` 为准备完成标志：true 表示关闭并锁定，界面显示 Closed；false 表示打开，显示 Open。F／R 继续依据同一准备状态检查，不以显示文案反向推断。

输入以 event.code 区分物理位置，小写、Shift 与 Caps Lock 等效，Ctrl／Alt／Meta 不误触。T／S 直接提速／减速，常亮且无数值，主仪表仅四项，移除Engine及百分比；W的Open／Closed状态保留在底部。中文由共享dom模块将汉字和中文标点单独增大1px，静态入口及动态文案统一处理；保持文本值、英文数字字号和既有节点缓存，不使用逐帧扫描或MutationObserver。所有英文只有首字母大写，OFF／ON 例外；未来标点采用 Comma／Period／Semicolon。

音效使用单个 Web Audio 上下文、复用振荡器与噪声缓冲区，发动机跟随启动进度及实际动力，风声跟随空速，轮胎声仅接地时出现，刹车加强摩擦声，电机声跟随收放状态。game.onEvent 触发短音和播报，逐帧 update 只更新持续声与倒数变化，相同 AudioParam 目标不重复排程，连续静音不重复取消声源，恢复时重新设置主增益。音效与播报默认开启，不设置声音开关，首次真实手势解锁；暂停、失焦、COMPLETE 和 RESULT 立即关闭主增益、停止短音并取消语音。恢复只读取当前持续状态，不排队重播；重开使用现有 runId 清理本局瞬态。参数集中 AUDIO。

Speech Synthesis 只选择 localService 的英文声音，优先匹配配置内的本机音色；没有本地英文语音时保留文字与合成音效。播报最多保留当前一句，新事件替换旧的普通句子，安全警告优先，单句最多 2.5 秒有效游戏时间；播报时环境声按原始目标音量降低，警报不降低。不可把接口接入或信号采样当作已通过实际女声音色／扬声器混音验收。

## 新增关卡与地景

新关卡只扩展LEVELS与JOURNEY，通用Flight／Mission不按城市分支。RouteWorld的地面山面、独立凸岩体与建筑包络为渲染和碰撞的共用来源；悬空岩体不进入heightAt。水幕只有可见面与穿越区域，岩石仍有实体检测。地面网格须显式包含海拔剖面折点，目的地入口后保持平面；AirportView整体应用目的地标高，机轮约束和接地使用同一标高。

一局仅有深圳与当前终点机场。跑道、机坪、地图目标、距离、进近与胜利统一读取route.destination，模板参数变化必须覆盖所有关卡。完整契约见[三关航线与机场](../design/07-航线与关卡.md#共用机场契约)。

## 准备耗时与资源预算

首屏从必需资源和基础模块就绪起计，2秒内显示标题、开始入口和轻量预览，资源下载耗时另记。开局从点击开始至可操控计时，包含加载、缓存、生成、编译、上传和四秒运镜；第一阶段默认5秒，本次按允许增加1秒的画质余量配置为6秒。真实任务可利用3秒Loading窗口，不额外空等；重开复用场景。`First screen visible`、`Scene prepared`、`Flight loading completed`和`Flight control ready`分别记录首屏、完整场景、加载和可操控时刻，不混用计时口径。

当前第一阶段发布资源预算为小于10 MB，不是必须占满的目标；当前山形、岩纹和树木均由代码生成，没有新增二进制模型或外部纹理下载。预生成属于必要时的后备方案，产物只能进忽略目录与部署包，不能提交Git。当前Pages资源整理流程继续复制源码与必要Three.js模块，未增加模型编译步骤。

GitHub Pages站点最大1 GB、带宽软限制100 GB／月，部署10分钟超时；自定义Actions构建不受每小时10次构建限制。发布大小与Git仓库历史独立核算，详见[官方限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)。

速度控制参数集中 FLIGHT.speedRate／speedBrakeRate／speedModeRatio／speedTapKmh；W 打开进度 p 的倍率 m=1+9p，提速基准为 speedRate/m，减速为 speedBrakeRate*m/10。speedTapRemaining为剩余km/h额度，同向点按累计、反向取消；末步收小施力，长按与点按共享同一股变速力。内部throttle为T请求的推进需求，请求完成后归零，不自动跟踪巡航速度，也不是停机条件。脚部视角复用场景与主飞机，绘制期间临时恢复机壳可见性并隐藏内舱，finally 恢复材质、可见性与裁剪状态；不新建 WebGL 上下文、地景或飞机模型。脚部小窗复用主视口已更新的同帧世界矩阵，绘制后恢复自动矩阵更新状态。两个小窗布局改变后更新缓存边界。

Flight.updateSpeedLimits使用当前密度、减速板和坡度计算平飞Vs与1.2Vs，失速判据仍为迎角；T请求中的正常阻力补偿排除分离／超速额外阻力并在低动压下衰减，无T请求不补动力。俯仰目标与实际操纵速率同源，反向按键从实际姿态开始；失速俯仰／滚转效能分别为当前动压下的85%／45%。失速气动回正同步移动目标，与持续俯仰输入对抗时最多占有效俯仰速率的50%，避免目标积压或输入响应反向，速度、位移和碰撞持续积分。Flight.stallGuidance按当前迎角恢复区与T故障提供顶部异常及失速事件文案。Game暂停与结算清空speedTapRemaining。Mission.flightSeconds只累计离地后有效飞行时间，遭遇捕获生成时的三维相遇预测，此后固定运动；任务elapsed仍从R放行起算。TrafficView使用同一birdScale／trafficScale与逻辑椭球，雁群镜像使用独立共享左翼几何，不向InstancedMesh写入负缩放矩阵。

## 第一阶段共享表面资源

`src/surface-assets.js`组织12份基础纹理、20份共享几何与11项纹理增强任务。首屏不等待这些工作；基础模型、碰撞与必要GPU对象完成后进入四秒运镜。当前按第一阶段资源预算验收，额外准备余量以`GAME.scenePrepareLimitSeconds`为准。发布仍是原生ES Modules，只保存生成代码、配置和种子，不增加模型／纹理下载。

机身80个径向分段，发动机使用64段外壳、空心进气道与32片弯掠叶片。主翼和尾翼使用保留原平面轮廓的弧面翼型，增加圆钝前缘、薄后缘、翼尖收薄与金属前缘；起落架补充支杆、轮毂紧固件与圆肩轮胎。机场补充窗框、屋顶设备和机库结构。基础几何在开始前生成、合批并预热；机轮与减速板保持独立动画，碰撞采样与关卡布局不变。

本游戏允许在READY、四秒INTRO、入舱后的STARTUP及已放行但尚未加速／位移的静止阶段继续补充细节。首次T指令或位移会按现有runId锁住本局生成窗口：先暂停队列并终止Worker，再处理提速，松开T不会恢复。飞行／滑跑中禁止继续生成、解码或上传。暂停和结果页可继续，恢复前同步停止；重开清除本局锁定并复用同一静态队列。R起算的任务时限不因可选细节生成而延长。

`src/generation-queue.js`用requestIdleCallback调度非紧急任务；真实Loading改为后台scheduler.postTask持续推进，批间scheduler.yield，不支持时用setTimeout。CPU批次目标4毫秒，高刷新率或长帧时收紧可选批次。纹理按行／256像素块、机身按截面、其他几何按对象设置让出点。像素及mip计算由模块Worker完成，ArrayBuffer直接转移；停止时终止Worker，未完成数据在下次许可窗口重算。异步读取只保存返回值，重新校验队列状态及当前窗口后才继续创建或上传。

静止等待时逐步把主要纹理从512提升至1024，岩纹与舱框细纹升至512，金属升至256。颜色纹理在线性空间生成mip层，数值纹理直接平均；GPU按每层32行分批上传，整张完成才替换材质，释放旧GPU对象。上下文丢失使用AbortController中止未提交上传，恢复后重传，防止采用失效进度。反射集中用于玻璃、蒙皮和金属，粗糙地面与森林不增加环境反射采样。共享纹理及mip的估算体积约48.1 MB，含单张待提交纹理时受64 MiB生成预算约束；该值不是发布体积，也不代表整个场景显存。

`src/surface-cache.js`通过IndexedDB保存原始像素、mip及几何属性／索引，键包含项目、生成器版本、配置哈希、关卡和种子。像素以512 KiB块读写，元数据最后提交；不完整或不匹配记录重新生成，旧配置记录按关卡清理。缓存不可用时退回内存，同页重开仍复用；命中持久缓存仍需初始化GPU对象。逻辑地形与查高继续使用同源世界数据，不混入旧视觉缓存。

部署仅包含源码、必要Three.js模块和模块Worker，兼容Pages项目子路径；生成缓存和部署副本均不加入Git。生成、Worker、编译、上传与真实帧耗时分别记录，不能用CPU提交耗时或绘制次数推断GPU速度。具体实测见[增强验收](validation.md#第一阶段材质与模型增强验收)。

## 程序版本与启动升级

`src/version.js` 的 `APP_VERSION` 是程序发布版本唯一来源，当前为1.0.1，独立于生成器版本5及缓存格式1；包描述与锁文件同步。Pages准备流程校验正式Release标签（`v1.0.1`或`1.0.1`），不匹配即失败，并写入同版本`version.json`，游戏标题栏显示版本。具体升级与发布规则见根目录`AGENTS.md`，不因整理部署文件自动发布。

启动先显示轻量预览与版本检查，再读取IndexedDB的`cloud-cockpit/meta/completed-version`。无历史为首次准备；有历史且版本不同显示“版本升级”、实际进度和失败重试入口，完成前不允许开始。同版本直接进入开始界面，不强制再等升级；当前关卡的资源始终按自身清单校验。首次／升级时完成32项基础数据及11项增强纹理的读取、增量生成、持久化与GPU准备，再清理未再引用的当前关卡生成记录，确认成功版本写入后开放开始。生成任务沿用4毫秒目标分批和Worker；升级耗时独立于点击开始计时。

缓存按项目、关卡、资源名称、生成器／格式版本及该项实际配置依赖生成键；程序版本和调度参数不使资源失效。旧整组配置键在配置完全一致时逐块迁移，不重新生成数据。更新前保留旧记录，完成后仅清理当前关卡未再引用的生成缓存；其他关卡按进入时的清单更新，不影响存档、设置或其他项目。失败可重试，部分完成数据复用；存储不可用时明确提示仅本次会话准备，成功版本不登记为持久完成。

## 碰撞反馈与鸟击限速

`Game.finish`区分实体损毁和非实体失败：撞地、障碍物及其他飞机携带destructive标记，进入CRASH。复用completionElapsed推进2.8秒特效，飞行积分、任务时钟、交通和activeSeconds均冻结，期间不接受飞行指令。暂停冻结特效，恢复后续播，结束后才显示RESULT；重复失败不会重启或提前结束特效。重开以现有runId和reset清理状态，成功仍走原COMPLETE反馈。

`src/impact-effects.js`在场景准备时预分配236个点粒子、24个实例碎片和一次闪光，加入既有材质编译／几何预热。运行时只更新uniform、实例矩阵和可见性，不创建几何、纹理或Worker；重开复用同一池。固定种子的小型初始参数和GPU对象与本会话绑定，代码即为完整配方，不额外持久化这些廉价缓冲；现有共享模型／纹理的IndexedDB缓存策略不变。火光／烟雾使用解析点精灵，不新增贴图、后处理或资源下载。音效继续由Web Audio复用噪声缓冲合成，暂停与结果静音。

`Mission`对每个雁群的hit状态去重，鸟击设定aircraft.birdStrike，独立于海拔动力故障。`Flight.maxSpeed`按现有463 km/h安全上界与route.birdStrikeSpeedRatio=0.8给出370 km/h上限；在受力积分后、位置积分前约束速度大小，保持三维方向。重复撞击不叠加，暂停／故障恢复不解除，重开恢复。UI显示持续限速状态，短提示不超过2.5秒；规则及边界见航程设计。

## 公制速度约定

速度状态和规则参数统一使用km/h：aircraft.airspeed／verticalSpeed、Flight的失速／安全／最高速度、结果最大／离地速度，以及FLIGHT／AERODYNAMICS／ROUTE／LEVELS中的速度阈值和交通速度均为同一单位。界面、起飞标记、进近、起落架、着陆、鸟击提示和结果页直接读取这些值，不再做节的换算；三关巡航约370／417／454 km/h，抬轮约269 km/h，进近296–333 km/h，安全接地不超过约352 km/h，起落架放出门槛约407 km/h。最高安全速度463 km/h，鸟击上限为370.4 km/h（显示370）。垂直速度与下降率也显示km/h，安全接地下降上限21.6 km/h。

位置、三维velocity与碰撞扫掠仍使用米／秒，以便正确计算力、重力和位置；仅在受力／坐标积分边界通过FLIGHT.kmhPerMps=3.6换算，气动角度按三维velocity求取。加速度仍为m/s²。单位迁移不改质量、推力、气动曲线、关卡时限或运动轨迹，不提交生成缓存的新副本；速度单位不参与与其无关的共享几何／像素缓存失效。


姿态卡交通示意由`PreviewTraffic`在场景准备时创建6个可复用目标槽及箭头缓冲，飞机／雁群轮廓共用两份极小几何，不新增像素纹理。它们属于可直接重建的小型GPU显示对象，初始化成本低，不单独持久化；已有大型模型／像素缓存保持复用。位置直接读取TrafficView的同帧插值结果，在同一参考航向下均匀变换相对三维坐标；图标为辨认用途，不作为碰撞尺寸。危险色读取Mission.danger，不另写接近判断；A关闭、暂停、重开与主交通一致。目的地跑道通过route.destination统一6000×240米，AirportView边灯按实际长度铺设，Flight安全接地和滑跑边界同源；机场标高保持同源。


张家界石柱的截面由`createRockFootprint`按独立种子和形态参数做半平面裁切，保留凸性；各高度截面同源生成可见三角面和碰撞平面。使用顶点均值作为内部参照点统一法线方向，保留原中心、半径、高度和布局随机流。峰顶树木由实际顶面多边形内插落位；暖黄、浅黄、褐色风化和绿色顶面在场景准备时写入顶点颜色，复用既有岩纹及材质，不在游玩中重建。截面与逻辑凸体每次按当前配置轻量生成，不读旧岩柱几何缓存；共享模型／像素配方未改，继续复用兼容IndexedDB资源。

目的地停放布局使用AIRPORT_TRAFFIC独立固定种子，三关各4架客机及8辆卡车，渲染和碰撞共用位置／朝向／机场标高。停放客机直接实例化已有客机几何并克隆一组材质，避免玩家入舱淡出影响它们；卡车低面数几何在场景准备时建立一次并复用，不持久化这份极小基本体组合，不新增模型或像素文件。共享飞机几何／纹理仍走已有持久缓存，无数据配方变化，不修改生成器版本。开局前统一GPU预热，碰撞时只改变已有矩阵与状态。移除停机圈及其标签纹理，地图星标指向跑道中部；安全接地后整机平面包络位于跑道内、速度≤7.2 km/h连续1秒完成，机坪不计成功。卡车每辆只扣当前速度10%一次，抛落先完成才接受成功；暂停／重开沿用Game时钟和Mission状态。

世界水平位移统一经过config.worldHorizontalSpeed（当前2倍），Flight仅在X／Z坐标积分处使用，空速、受力、T／S额度、姿态响应与Y积分保留；Mission的交通预测和相对速度、PreviewTraffic航迹箭头、卡车抛飞继承动量使用同一倍率，交通velocity保存世界坐标速度，不能再次放大。地面、地标、海拔剖面和目的地已绑定新布局；总里程为26.4／35／44.8公里，进近距离和目标下降曲线按同一空间倍率换算，倒计时不变。clusterZ只移动景点群，几何尺寸不伸缩；地形种子读取sourcePosition，移动山群不重抽山脊。

新增过渡带来自JOURNEY.transitions：小丘12分段，显示、碰撞和查高共用RouteWorld生成的网格；草坡与平地使用同一草纹和世界UV以隐藏底座边缘，溪流与草地不增加像素资源。LandscapeView.prepare复用GenerationQueue逐段／逐座创建显示对象，Renderer.prepare等待该队列结束、登记新材质并统一预热，随后才开放操控。新增低成本逻辑网格和基本显示对象直接重建，重开保留，不为几千个顶点单独引入持久化恢复开销；共享模型与纹理仍使用32项基础／11项增强持久缓存，现有配方未变，生成器5、缓存格式1与尚未发布的程序1.0.1继续使用。

滨海前段由coastal-terrain.js集中定义海岸、机场陆地平台和连接道路；RouteWorld初始化一次16434顶点的逻辑海岸网格，显示复用同一顶点，查高按同一非均匀网格三角形插值，水下高度由可见海平面覆盖。机场及机坪保持原标高；草地、溪流与机场树木按实际陆地过滤。第一关无山体／小丘／瀑布岩壁，后续丹霞、石柱与两道空中瀑布保留。CoastalView通过现有GenerationQueue准备海面和沿岸高架高速：桥面、三道护栏与桥墩共440个实例构件，位置、尺寸和朝向直接读取World碰撞数据；有向六平面保留桥下通行空间。海面不使用新增像素资源，波纹只更新既有材质时间，暂停冻结，GPU预热完成后才开放操控。逻辑网格为轻量确定性计算，显示对象同页重开复用；共享几何和像素缓存配方未改变，生成器5、缓存格式1和未发布程序1.0.1保持。


`windshield-damage.js`预创建两组独立蛛网裂纹与轻量玻璃面，首次／二次鸟击分别显示一组；复用相机局部坐标随窗口缩放，暂停沿用有效时钟。几何为极小固定种子线段／面片，在驾驶舱准备时创建并统一GPU预热，同页重开复用；没有贴图、解码或昂贵计算，单独持久读写成本高于重建，因此沿用轻量基本体的内存例外，不改变共享模型／像素配方。鸟击计数归Aircraft，每雁群一次；Flight派生T故障，指令与持续受力均门控，Mission在第二次撞击清空待执行正向额度。未放轮下降警告由Flight统一产生，UI／Audio读取同一危险条件，触地走原有CRASH流程。


`flight-status`只承载当前最重要的一条异常警告，贴近屏幕上沿并使用深黄／深红背景；正常时隐藏。已移除常规操作教学、抬轮目标及所有角度／扩展气动读数，基本仪表和按键图例保留，右侧飞机图不包含安全文字。Prompts仅保留短时操作／奖励反馈，安全状态直接读取Flight／Mission，不用事件文本维持过期警告；放轮因速度受阻时记录操作条件，在速度恢复或放轮后解除顶部提醒。AircraftPreview只放大有交通时的本机显示，继续复用既有模型与材质；预览相机、其他交通符号比例、相对位置换算及缓存配方保持，黄色／红色用更深的状态色。
