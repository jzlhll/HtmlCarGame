## 运行入口

线上托管、独立博客入口和仅正式 Release 更新规则见 [GitHub Pages 发布](github-pages.md)。

`npm ci` 安装锁定版本的 Three.js，`npm start` 启动内置 Node.js 静态服务，默认地址为 `http://localhost:5173`，可用 `PORT=5184 npm start` 指定其他端口，只监听本机回环地址。依赖安装完成后无需联网，无构建步骤，无外部模型或图片下载。macOS 提供根目录 `启动游戏.command`。

通过 HTTP 服务加载 ES 模块，不直接双击 `index.html`。服务只提供入口页面、`src` 与依赖文件，不提供项目文档或隐藏文件。

预览前的端口占用、服务归属、启动成功和浏览器加载检查见[常规验证流程](validation.md#浏览器端口与服务检查)。

缺少内置浏览器工具时，统一使用通用工具目录中的 `playwright-core` 驱动已安装的 Google Chrome，跨项目共享依赖与验证脚本，具体约定见[轻量验证方案](validation.md#轻量-playwright-验证方案)。

模型工具通过 `three/addons/` 子路径导入；入口的 import map 同时映射 `three` 和 addons 前缀，依赖目录调整时统一修改入口映射。

逻辑道路位置使用累计弧长 `s` 和横向偏移 `d`。`Road.at` 提供高度与坡度；每次显示将世界位置转换为玩家附近的局部坐标，循环道路跨轮沿上一轮终点连接，不重置累计距离。道路和景物使用固定容量实例或网格，车流容量从 88 辆起按有效运行时间增长，最多 160 辆；车辆按车型和颜色回收复用。

连续碰撞使用每秒 120 步的分离轴平移扫掠，车辆盒体采用本步起始位置的道路切线方向，纵向长度按坡度投影到水平面。首次接触面决定分类：侧面且纵向重叠足够为吞吃，双方端面中央区域的横向投影重叠才按追尾；擦角及已有重叠只横向分离。路面障碍采用车轮与履带采样点对椭圆区域的连续接触，并加入相同的事件时序。坑洞弹跳仅抬升显示模型，逻辑碰撞仍在道路平面；步内曲线方向变化很小，但该实现不是完整刚体旋转扫掠，若加入真实腾空、急弯或自由转向，需要扩展三维旋转连续碰撞。

同一步先处理最早接触、保护结束或饥饿到期，同刻按开始时车型分类，致命车辆或墙体优先。否则汇总有效吞吃及同级追尾／奶牛积分；闪电按本组开始车型消耗防御，耗尽时固定低一级积分优先，自行车耗尽死亡。即时车型确定后，若无吞吃则按当时实际车型扣饥饿积分；只预存截止时间，不缓存扣分量。换车型补满防御，降级保护两秒；死亡锁定实际事件时刻。天降炮弹在逻辑步末独立结算，防御耗尽立即换车并保护。

同向与对向车道采用相同的侧碰、追尾和等级规则。分类依据首次接触形态、车型等级与氮气喷气状态；目标方向影响相对接近速度，不阻止对向吞吃。

## 绘制与更新策略

- 新局及返回首页时归还旧车辆与动画残影，清空车辆 ID 映射并保留模型池；绘制前同时核对车流对象身份，避免不同对局重合 ID 复用错误外观。系统车辆保留独立模型变换，部件按共享几何、材质及阴影属性合批，原模型不加入场景树；正常车辆和残影共用批次。车轮、转向灯与双闪保持独立动画，镜头及阴影视锥都不可见的车辆跳过提交；实例缓冲按需求扩容，只上传有效实例范围。
- 阔叶树、松树、树干、岩石、湖泊、道路标线和路柱在实例矩阵或数量更新后重算包围球，包含空批次与换局情况；少量爆炸粒子及季节粒子关闭视锥剔除，避免沿用旧范围而消失。
- 吞吃与损毁残影在行驶和死亡动画中继续计时，暂停冻结；结算立即回收剩余残影。已标记移除的车辆不再创建正常模型，避免同一步吞吃后死亡时重复显示。
- 玩家车辆在死亡动画末尾隐藏，死亡结算及其后续重绘保持隐藏，只有新局或返回首页时恢复；主动结束的结算保留车辆。
- 行驶、被抓和死亡动画期间持续调度帧。首页、暂停和结算只在状态切换、尺寸变化或镜头尚未稳定时绘制；镜头缓动期间仅更新相机，稳定后停止帧循环。重新唤醒时从当前时刻计时，不补算静止时间。
- 道路九条条带共享 109 个常规中心采样，截止点额外插入同站点的宽、窄边界采样，并按实际数量绘制；复用宽度、方向、坡度与法线，通过横向偏移得到两侧顶点，截止处不插值生成斜边，曲线和上下坡保持连续。
- 道路、标线、树木、施工与路面障碍的静态几何每十米更新一次，其余帧通过父节点转换玩家参考系，保持连续移动；沿五米采样点对齐道路网格。渲染像素比最高为 1.5；起步预热一秒后，连续两秒平均帧率低于 45 时降低像素比，每次减少 0.25，最低 0.75，保留本页已选档位以避免画质反复跳变。
- 主路、副路与后方车辆统一由 `Traffic.stepMain` 推进，先保存步初位置及路线，再计算临近避让或随机换道，不调整跟车速度。每步同步 `previous.route`，保证汇回主路后正常接触主路冰区。`resolveContacts` 按纵向候选连续检测系统车辆及道路物体，接触事件按时刻排序；不同等级撞毁低级，同级惯性弹开，碰撞记录只保留持续接触及附近物体。
- 道路生成时单独保存收窄／截止路段及截止墙路段。关闭与墙体查询只扫描对应的小列表，并换算本轮与下一轮的累计位置，不反复遍历完整道路计划。
- 车道宽度通过二分查询所在路段，不创建路段副本；车道开放状态直接查询施工计划，跳过施工列表及对象副本的分配。
- 系统车每步共用附近墙、施工、坑洞、泥洞、奶牛和河道列表。普通车仅在预计 3.5 秒或至少 16 米范围内临近碰撞时闪灯尝试邻道；没有安全空隙则保持运动。墙及路障在边界修正前连续扫掠，触碰后损毁回收。
- 路边布局只缓存附近至多八个候选区块，驶离后释放，换道路时清空。建筑、农田、围栏与奶牛静态部件只在区块进出时改写实例矩阵，每帧通过父节点转换玩家参考系，并单独更新奶牛腿、尾巴动画；季节材质只在季节值变化时更新。
- 左侧仪表显示本局运行时间，使用有效行驶时间按分秒显示，暂停、死亡与结算时停止，新局归零。仪表缓存已显示的整数距离、整秒时间、取整速度、车型与升级积分，仅数值变化时格式化并写入页面；速度条保持连续比例，比例未变时跳过写入。

施工实例上限为 64 块铺面、192 组锥桶、8 个路障和4个预告标志。`convoy` 保存慢队身份、速度、净距；关闭车道并道后解除队形绑定，保留低速目标。双闪随有效时间变化，复用时清理。

坑洞弹跳 0.65 秒，横向冲量按 4.4 m/s² 衰减；泥斑与限速保持 8 秒。障碍接触记录只留近处，绘制批次复用，空批次隐藏。场景每约 90 米检查地块，每批容量 1024；湖泊最多四处。左侧仪表标签为 14px，单位与氮气状态为 13px，浮动提示及后车提示为 14px，界面不显示道路文字提示。

## 首版边界

桌面键盘操作；无移动触控、回放与存档导入导出。音效由 `src/audio.js` 用 Web Audio 实时合成，不加载音频文件，参数集中在 `config.js` 的 `AUDIO`；环境声按与玩家的距离衰减并带声像，事件声跟随游戏逻辑触发，暂停与结算静音，声音清单与空间模型见[音效系统](../design/12-音效系统.md)。系统车遵守系统间约束，不主动避让玩家。正常生成通过车道和净距约束留下空间，玩家仍需判断实时变道、对向交通及道路关闭风险。

一级车的头盔骑手、圆润油箱及其他静态部件在模型模板中按材质合并，仅两只车轮保持独立，合计十个网格；玩家、系统车和动画残影共用缓存模板及实例批次，泥巴涂层按合并后的部件生成。`BICYCLE_TIRE_WIDTH` 配置缩放前 0.14 米的轮胎宽度；模型及坑洞、泥洞接触共用缩放后的实际宽度。

`TREE_SCENERY` 配置 150 棵实例容量、30% 松树比例、4.8–7.2 米树高和 1.3–1.9 米冠幅缩放。`tree-model.js` 将多簇树冠和三层松针几何各自合并为一个共享模型，顶点明暗随季节底色变化；树干合并分叉枝条。布局按道路种子随机高度、冠幅与旋转，沿用十米静态更新和道路净空检查，仅上传有效实例范围，远行及换局不累计对象。

复杂多车连锁偏移和长时间道路循环仍需在实际游玩中持续观察和调参。当前不引入物理引擎；修改车型尺寸、曲率或最高速度时，需同时检查吞吃判定、并道空间和预警距离。

同级侧碰惯性由 `SIDE_BOUNCE` 控制；系统车从下一步开始横移，取消并道后认领最近车道。未喷气时自行车同级追尾返回 `bicycleRearFatal`，不走负分缓冲。喷气期间同级追尾返回 `knockaway`，低级追尾返回 `eat`；同级侧碰仍返回 `eat`，擦角与已有重叠仍只分离。

## 随机天气

`SeasonalWeather` 使用独立种子序列和有效时间，规则见[四季场景](../design/04-四季场景.md)。`DistanceFog` 通过逆相机矩阵还原片元水平位置，按与玩家距离增浓，包含实例、父节点及关闭普通雾的特效；材质只注册一次，切换只更新共享参数。天气粒子复用，冰冻车身实例仅在实际数量超限时扩容。雷击伤害取 `VEHICLE_DEFENSE.lightning`。

## 白马事件

拾取与强化边界纳入 `Game.collisionStep`，保护时先撞飞目标，不执行普通伤害或吞吃；饥饿截止延后，氮气保留。静态缓存校验 `WhiteHorseEvent.revision`，碎片最多 8 组、每组 6 个。规则见[白马事件](../design/11-白马事件.md)。

## 警车追击

`PoliceEvent` 独立管理距离窗口、车道评分及固定间隔撒网；捕捞网沿玩家当前路线向前量取 `max(netAheadMin, 当前车速/3.6 × netLeadSeconds)` 米（默认至少40米、2秒车程），保持生成时横向偏移，生成后位置固定、立即生效并存活6秒，不以警车距离门槛延后发射；渔网复用世界坐标扫掠，查询返回最早接触且不写命中状态，规则见[警车追击](../design/13-警车追击.md)。`collisionStep` 统一候选：渔网命中进入 `CAUGHT` 冻结局面，`animate` 推进缩小拖拽，完成后进入 `QUIZ`；车身接触直接弹题，答题或调试复活保护期间不检测二者。题目携带 `subject`（`math` / `chinese` / `english`），显示时以 `performance.now()` 设置数学45秒、语文与英语30秒的截止时间；`QUIZ` 持续更新倒计时，驾驶逻辑冻结，提交答案也校验截止时间。`rescueUsed` 记录已用救援次数，每局重置为 0；`RESCUE_LIMIT` 默认 2，`die` 在前两次非答题致命事件中递增计数并改为 `policeContact(true)`，次数用尽后再次死亡正常结算，警车拦查答题不消耗救援次数；`quiz.rescue` 区分救援题，答对调用 `revive(true)` 恢复车辆，沿当前路线实际弧长清空前方 `REVIVE_CLEAR_AHEAD`（50米）内所有车道、双向车流，副路出口后接主路；清理车辆标记 `remove`，渲染立即隐藏且不计吞吃或回气，普通警车题答对撤离重排。碰撞结算进入 `QUIZ` 后立即停止当前步，复活保护覆盖墙与道路障碍。答错按 `quizWrong`、超时按 `quizTimeout` 直接结算，结算页展示 `failedQuiz` 中填回正确答案的原题，不重复展示选项，不再触发救援，调试局也结束且不写榜。警笛按距离和方向更新，暂停、被抓与答题静音。

## 防御与速度显示

左侧防御仪表使用当前车型满防御归一化显示百分比，并缓存上次显示值。玩家起始速度由 `PLAYER_START_SPEED` 配置为57.5 km/h，正常速度上限为 110／130／145／145／145 km/h；对向普通巡航采用基础交通速度乘以 1.44 后按 km/h 四舍五入，环境及碰撞产生的实际速度变化仍连续处理。`NITRO.maxSpeed` 将各车型无惩罚喷气上限统一为215 km/h，`Nitro.limit` 的停喷回落共用该上限。

## 高架与低沉道路

`Road.structures` 保存高架和低沉事件，使用独立种子序列；`infrastructure` 输出带轮次的稳定事件标识。`elevation` 提供平滑坡道及平坦桥面、谷底，`groundElevation` 保持桥下地面并允许河谷地面降低。道路采样保存独立地面高差，公路条带与地面分开布置。

`RoadInfrastructure` 为每座铁路高架安排一次火车事件，按稳定结构标识去重。距桥面中央铁路交叉点的剩余主路弧长不大于 `当前车速/3.6 × ROAD_INFRASTRUCTURE.trainLeadSeconds` 时立即生成，默认提前量 2.5 秒；停车不触发，不预设固定延时。火车从 `-trainSpeed × trainLeadSeconds` 的横向位置驶出，保持当前车速时玩家和火车中心约同时抵达交叉点；生成后按有效时间独立前进，不因变速刷新，暂停冻结，新局清空。`GameAudio.update` 跟随同一 `trains` 列表计算轮轨声的音量、声像与随经过时间加快的节奏，不播放汽笛，暂停与结算静音。没有平交道口、信号灯、停止线、铁路制动或火车碰撞路径。河道谷底入口沿用连续接触减半，`dipHits` 保证只触发一次，干燥谷地不限速。

`InfrastructureView` 按材质、投影开关和静态／动态用途区分实例批次。护栏、桥面、桥墩、挡墙、铁路和河道由 `GameRenderer.updateStatic` 每十米重建一次，其余帧共用静态父节点转换；缓存只保留附近结构，新局清空。水纹颜色与六节火车逐帧按有效时间更新，暂停冻结。所有非空批次通过 `addUpdateRange(0, count * 16)` 仅上传有效矩阵范围，空批次隐藏并跳过上传。道路采用蓝灰、青色导向架与金属护栏，主路、副路和高架护栏及立柱均不投射阴影；`InfrastructureView` 按材质和投影开关区分批次，其他独立实例仍保留各自投影设置；路边树木和楼房使用独立地面高度。路段不显示界面文字预告；缓行事件不弹任何提示。

## 分叉道路

`ROAD_FORKS` 管理分叉投放、880–1760 米路线跨度、800–2000 米副路实际弧长及中段 40–60 米道路边缘空隙、副路坑洞和天气概率；`ROAD_INFRASTRUCTURE.gapMin/gapMax` 为建筑道路之间预留 800–1160 米空间（间距缩半使起伏路段频率加倍，较窄区间放不下分叉的最小跨度，分叉只落在较宽的间距里）。`Road` 在地面平坦、车道数稳定且无施工的区间生成分叉，保存两条路径采样及实际弧长；弯曲幅度随机分配，不从曲率推断路线身份。`route` 使用轮次和分叉编号组成稳定标识，主路为 `null`，车辆在入口选择副路后持续沿其中心线移动，至出口回归主路。`pathScale` 将物理速度换算为公共道路里程，累计实际距离作为成绩；`BranchRoadView` 与主路共用配色，静态几何按十米缓存更新，110 个采样点覆盖前后 540 米可视区间。

副路车辆独立投放，运动、避让及系统碰撞与主路统一调度；车身连续碰撞使用路线几何，路面坑洞使用路线内相对横向坐标。副路天气以 85% 概率检查，跨季节随机，天气之间隔 3–7 秒，不受普通每分钟场次限制。白马、特效、雾中心和摄像机均使用当前路线。

`ROADBLOCKS` 配置 150 秒后启用的独立 X 路障，`Road.blockadesAfter` 固定前方至少 240 米的启用边界并增加 `revision`；`roadworks` 与 `laneOpen` 同步过滤未启用候选，复用施工的碰撞和车流避让流程，独立绘制红色 X，不生成施工铺面、锥桶或绕行牌。`SHELL.frequencyAfterSeconds` 配置炮击加密阶段，150 秒后采用 5–10 秒间隔并缩短旧排程的剩余等待。

`ROAD_DIFFICULTY` 配置 150 秒阶段、60 米前方预留距离、400 米平滑收窄。`fourLane` 集中配置后期随机变道加成 25 个百分点、4–7 秒检查间隔及 25% 危险属性概率。`Road.isFourLanePhase` 以玩家越过永久收窄过渡终点作为统一判断，前期自然四车道不触发；`Road.narrowAfter` 固定一次收窄位置，主、副路同步收窄，不等待分叉结束，后续主副路及跨轮道路永久四车道；`revision` 触发静态几何即时刷新，过滤已取消外侧车道的墙、施工和路面障碍。暂停冻结，新局构造新 `Road` 清空该阶段。

`MANUAL_ACCELERATION` 只配置额外加速度 35：未到车型正常最高速度（含泥巴、河道与天气限速）时按住上键在自动提速基础上每秒额外增加35 km/h，直达最高速，允许零速起步且不消耗氮气；持续按住达到车型最高速后自动接续喷气，无需松开再按；达到喷气上限仍继续消耗氮气。刹车、刮边和冰冻优先，泥巴及河道仍限制最高速度。


## 热路径与缓存

逻辑保持 120Hz，连续事件仍按接触、保护与饥饿边界切分。`Road.fork`、`route`、基础设施、施工和截止墙共享只读跨轮记录，`ROAD_CACHE.maxLaps` 将道路与障碍缓存分别限制在四轮；收窄阶段清除路线宽度缓存，新局更换道路与车流实例。路线标识在缓存命中后不再拆分字符串。`dip` 与地面高度直接查询种子计划，不创建结构列表；范围查询支持调用方独立持有并复用输出数组，坐标查询支持输出对象，默认调用仍返回独立坐标，避免保留值被后续查询覆盖。

`Game.collisionStep` 在整步开始时查询静态候选，窗口按最高白马速度与全路最小路径比例保留余量，升级和拾取白马后的剩余运动仍在窗口内。远处车辆先剪枝再填写运动快照，事件直接挂目标引用，候选、同刻事件、分离集合和同步扫掠包围盒复用，事件保留独立接触点。`Traffic` 的静态障碍窗口每十米及道路阶段变化时重建，移动奶牛快照逐步同步；危险判断直接读取车辆字段，系统碰撞复用排序列表、运动快照和接触集合。换道安全判断每次读取当前车流，不仅按横向位置缓存。

`Traffic` 每步按起始纵向位置排序并复用避让列表；临近危险只沿行驶方向查询，换道安全查询双向窗口，越过窗口后立即停止。窗口按本车速度、其他车当前及巡航目标的最高速度、双方车长留足余量，覆盖对向来车、减速后恢复及本步已经移动的车辆；汇流口仍检查主副路关联和正在进行的变道。步外查询回退到当前车流，下一步重建列表，新局更换车流实例。天气接触复用独立起止快照，保留步初路线。

`ROAD_RENDER.sampleCapacity` 将路面采样、各条带顶点及索引的初始容量统一设为 160 点。静态更新前按截止点数量估计最坏采样量，超限时同步扩容并释放旧几何，容量足够时复用缓冲。路边建筑的 1024 容量按形状、材质及动画状态分批计数，当前最多八个区块，即使全为最高层小镇，同一批次最多 800 件。

`DistanceFog` 在场景节点加入时注册子树与材质，绘制仅更新共享参数，动态增加的车型、特效和冰冻实例也走同一入口。坐标转换、闪电向量及车辆／奶牛 ID 集合复用；转向灯与预警灯通过命名引用访问，不依赖子节点顺序。
