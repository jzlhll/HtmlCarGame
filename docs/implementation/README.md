# 本机运行与实现结构

[返回设计总览](../README.md)

## 运行入口

`npm ci` 安装锁定版本的 Three.js，`npm start` 启动内置 Node.js 静态服务，默认地址为 `http://localhost:5173`，可用 `PORT=5184 npm start` 指定其他端口，只监听本机回环地址。依赖安装完成后无需联网，无构建步骤，无外部模型或图片下载。macOS 提供根目录 `启动游戏.command`。

通过 HTTP 服务加载 ES 模块，不直接双击 `index.html`。服务只提供入口页面、`src` 与依赖文件，不提供项目文档或隐藏文件。

预览前的端口占用、服务归属、启动成功和浏览器加载检查见[常规验证流程](validation.md#浏览器端口与服务检查)。

缺少内置浏览器工具时，统一使用通用工具目录中的 `playwright-core` 驱动已安装的 Google Chrome，跨项目共享依赖与验证脚本，具体约定见[轻量验证方案](validation.md#轻量-playwright-验证方案)。

模型工具通过 `three/addons/` 子路径导入；入口的 import map 同时映射 `three` 和 addons 前缀，依赖目录调整时统一修改入口映射。

## 模块职责

| 文件 | 职责 |
| --- | --- |
| `config.js` | 五车型尺寸、巡航速度、玩家上限、横移速度、整数成长值与公共插值 |
| `main.js` | 组装模块、固定逻辑步、按需帧调度、页面失焦与跨标签存档变化 |
| `input.js` | 页面捕获游戏按键、上箭头低速加速及持续喷气、左右横移与侧移时长累计、下箭头刹车、空格重复保护与焦点恢复；保留编辑输入和浏览器快捷键 |
| `game.js` | 游戏状态、积分、速度限制、碰撞与饥饿事件分组、升级降级、死亡、调试复活与单次结算 |
| `collision.js` | 分离轴连续接触、接触边裁剪、侧碰／端面中央／擦角分类与横向分离 |
| `driving.js` | 连续氮气槽、吞吃回气、按住喷气和松开回落与上限 |
| `infrastructure.js` / `infrastructure-view.js` | 种子道路事件、桥下火车安排、河道减速与桥梁铁路河道实例化 |
| `fortification-view.js` | 双侧碉堡、塔楼及转向炮口模型复用 |
| `combat.js` | 双侧外围建筑投放、建筑射击触发、独立冷却与概率、射弹寿命、墙体遮挡和连续命中 |
| `road.js` | 种子有限道路计划、平滑曲率、三维弧长采样、上下坡、跨轮平移连接、车道过渡与墙位置 |
| `branch-road-view.js` | 绘制与主路相同样式的副路条带和车道标线 |
| `weather.js` | 按有效时间调度季节天气，管理雷击与冰区的连续接触、横风和冰冻限速 |
| `weather-view.js` | 复用雨雪、风线、落点、电光及冰冻外观实例，冰冻实例按实际车流需求扩容 |
| `white-horse.js` | 分钟白马投放、任意接触拾取、强化速度与距离、保护时间边界及有限撞破记录 |
| `white-horse-view.js` | 白马四肢奔跑、透明保护罩与末尾闪烁、固定容量撞飞碎片 |
| `crossings.js` | 低概率奶牛队伍横穿、有限队伍生命周期与暂停冻结 |
| `hazards.js` | 稀疏坑洞与泥洞计划、椭圆轮迹连续接触、每轮障碍身份与接触记录 |
| `traffic.js` | 有限前后车流、安全投放与回收、后车接近查询、固定巡航、系统临近避让及危险变道决策、预告与回正 |
| `models.js` | 五类低多边形车辆、横穿奶牛及白马，复用几何与材质；车辆上无等级标识 |
| `tree-model.js` | 簇状阔叶树冠、分层松树冠与分叉树干的共享几何 |
| `render.js` | 相对坐标、静态道路缓存、实例化景物、车辆池、四季材质混合、效果与自适应分辨率 |
| `traffic-view.js` | 系统车辆和残影的部件实例合批、镜头及阴影视锥筛选、实例缓冲区复用与扩容 |
| `scenery.js` | 附近地块布局缓存；楼房、谷仓、粮仓、作物、围栏及奶牛静态部件与动画的独立实例批次 |
| `roadworks-view.js` | 施工 X 标志、前后路障、锥桶和分块施工铺面的固定容量复用 |
| `storage.js` | 单键版本存档、五级规则校验、旧缓存清除、排名与存储异常处理 |
| `ui.js` / `style.css` | 游戏信息、危险提示、暂停窗口、结算和记录 |

逻辑道路位置使用累计弧长 `s` 和横向偏移 `d`。`Road.at` 提供高度与坡度；每次显示将世界位置转换为玩家附近的局部坐标，循环道路跨轮沿上一轮终点连接，不重置累计距离。道路和景物使用固定容量实例或网格，车流容量从 88 辆起按有效运行时间增长，最多 160 辆；车辆按车型和颜色回收复用。

连续碰撞使用每秒 120 步的分离轴平移扫掠，车辆盒体采用本步起始位置的道路切线方向，纵向长度按坡度投影到水平面。首次接触面决定分类：侧面且纵向重叠足够为吞吃，双方端面中央区域的横向投影重叠才按追尾；擦角及已有重叠只横向分离。路面障碍采用车轮与履带采样点对椭圆区域的连续接触，并加入相同的事件时序。坑洞弹跳仅抬升显示模型，逻辑碰撞仍在道路平面；步内曲线方向变化很小，但该实现不是完整刚体旋转扫掠，若加入真实腾空、急弯或自由转向，需要扩展三维旋转连续碰撞。

同一步先处理最早接触、保护结束或饥饿到期，同刻按开始时车型分类，致命车辆或墙体优先。否则汇总有效吞吃及同级追尾／奶牛积分；射弹按本组开始车型消耗防御，耗尽时固定低一级积分优先，自行车耗尽死亡。即时车型确定后，若无吞吃则按当时实际车型扣饥饿积分；只预存截止时间，不缓存扣分量。换车型补满防御，降级保护两秒；死亡锁定实际事件时刻。

同向与对向车道采用相同的侧碰、追尾和等级规则。分类仅依据首次接触形态与车型等级；目标方向影响相对接近速度，不阻止对向吞吃。

## 绘制与更新策略

- 新局及返回首页时归还旧车辆与动画残影，清空车辆 ID 映射并保留模型池；绘制前同时核对车流对象身份，避免不同对局重合 ID 复用错误外观。系统车辆保留独立模型变换，部件按共享几何、材质及阴影属性合批，原模型不加入场景树；正常车辆和残影共用批次。车轮、转向灯与双闪保持独立动画，镜头及阴影视锥都不可见的车辆跳过提交；实例缓冲按需求扩容，只上传有效实例范围。
- 阔叶树、松树、树干、岩石、湖泊、道路标线和路柱在实例矩阵或数量更新后重算包围球，包含空批次与换局情况；少量爆炸粒子及季节粒子关闭视锥剔除，避免沿用旧范围而消失。
- 吞吃与损毁残影在行驶和死亡动画中继续计时，暂停冻结；结算立即回收剩余残影。已标记移除的车辆不再创建正常模型，避免同一步吞吃后死亡时重复显示。
- 玩家车辆在死亡动画末尾隐藏，死亡结算及其后续重绘保持隐藏，只有新局或返回首页时恢复；主动结束的结算保留车辆。
- 行驶和死亡动画期间持续调度帧。首页、暂停和结算只在状态切换、尺寸变化或镜头尚未稳定时绘制；镜头缓动期间仅更新相机，稳定后停止帧循环。重新唤醒时从当前时刻计时，不补算静止时间。
- 道路九条条带共享 109 个常规中心采样，截止点额外插入同站点的宽、窄边界采样，并按实际数量绘制；复用宽度、方向、坡度与法线，通过横向偏移得到两侧顶点，截止处不插值生成斜边，曲线和上下坡保持连续。
- 道路、标线、树木、施工与路面障碍的静态几何每十米更新一次，其余帧通过父节点转换玩家参考系，保持连续移动；沿五米采样点对齐道路网格。渲染像素比最高为 1.5；起步预热一秒后，连续两秒平均帧率低于 45 时降低像素比，每次减少 0.25，最低 0.75，保留本页已选档位以避免画质反复跳变。
- 主路、副路与后方车辆统一由 `Traffic.stepMain` 推进，先保存步初位置及路线，再计算临近避让或随机换道，不调整跟车速度。每步同步 `previous.route`，保证汇回主路后正常接触主路冰区。`resolveContacts` 按纵向候选连续检测系统车辆及道路物体，接触事件按时刻排序；不同等级撞毁低级，同级惯性弹开，碰撞记录只保留持续接触及附近物体。
- 道路生成时单独保存收窄／截止路段及截止墙路段。关闭与墙体查询只扫描对应的小列表，并换算本轮与下一轮的累计位置，不反复遍历完整道路计划。
- 车道宽度通过二分查询所在路段，不创建路段副本；车道开放状态直接查询施工计划，跳过施工列表及对象副本的分配。
- 系统车每步共用附近墙、施工、坑洞、泥洞、奶牛和河道列表。普通车仅在预计 3.5 秒或至少 16 米范围内临近碰撞时闪灯尝试邻道；没有安全空隙则保持运动。墙及路障在边界修正前连续扫掠，触碰后损毁回收。
- 路边布局只缓存附近至多八个候选区块，驶离后释放，换道路时清空。建筑、农田、围栏与奶牛静态部件只在区块进出时改写实例矩阵，每帧通过父节点转换玩家参考系，并单独更新奶牛腿、尾巴动画；季节材质只在季节值变化时更新。
- 左侧仪表显示本局运行时间，使用有效行驶时间按分秒显示，暂停、死亡与结算时停止，新局归零。仪表缓存已显示的整数距离、整秒时间、取整速度、车型与升级积分，仅数值变化时格式化并写入页面；速度条保持连续比例，比例未变时跳过写入。

## 数值与可调整入口

- `ROADWORKS` 配置首个候选 380 米、候选间隔 400 米、出现概率 50%、封闭长度随机整数 30–100 米、预警距离 240 米和占用宽度 3.4 米。`Road.roadworks` 按累计距离查询施工段，`laneOpen` 同时检查车道数与施工占用，`stable` 查询道路切换区。普通 NPC 临近施工时闪灯并道，危险车不检查空隙；实际接触损毁；玩家施工接触沿 `s/d` 连续扫掠，不受弯道长矩形误差影响。施工绘制最多 64 块铺面、192 组锥桶、8 个路障和4个预告标志，随附近区间更新，不随里程增长。
- `SLOW_TRAFFIC` 配置每队 3–7 辆、目标速度 10–30 km/h、同队净距 2.5–4 米、首次检查 8–14 秒、后续每 14–24 秒按 65% 概率尝试。候选队头位于前方 338–430 米，队尾至少在前方 240 米；最多五次空间候选，整队生成失败则撤销本次新增车辆。双车道最多一队、三车道最多两队，车辆总量受当前密度容量约束；上一队伍离场前不再安排新事件。`convoy` 保存队伍身份、固定速度和净距，仅同队投放覆盖普通净距；关闭车道并道后解除队形绑定，低速目标保持。双闪随有效游戏时间变化，暂停冻结，复用车辆及动画时清理显示状态。

- 车型顺序为自行车、三轮车、小汽车、卡车、坦克。三轮车为玩家和交通车辆共有的独立车型；三级交通统一使用小汽车模型，发动机盖、斜面座舱与保险杠形成轿车轮廓，左右后视镜放大提亮，无竖立排气管。每类交通车六种配色，外观与颜色在生成时固定，按等级和颜色分池回收；玩家保持金色。
- 车型参数集中在 `config.js`，`MAX_RANK` 从车型表推导，统一用于升级、满级、坦克模型与履带、火箭弹和车流权重。玩家速度上限为 90／110／125／125／125 km/h，速度条按当前车型正常上限显示比例，交通车辆速度保持独立配置。
- `XP` 是车型门槛与吞吃价值 1／2／6／18／54，`UPGRADE_POINTS` 提供下一车型门槛。`player.xp` 保存唯一总积分，开局为 1；吞吃直接累加，`eat` 加分时先封顶，同车型吞吃不恢复防御；`grow` 同样限制上限并统一确定实际车型，吞吃和积分扣减引起的升降级保留积分，防御耗尽则设为低一级门槛，总分封顶 `XP[MAX_RANK]` 即 54，满级吞吃仍计数量并重置饥饿计时。左侧显示车型、总积分／门槛和当前防御百分比，坦克分母为 54，不显示基础或额外标签及“分”单位；进度条封顶 100%。`ONCOMING_SPEED_SCALE` 为 1.44，对向巡航使用同车型基础速度区间的 144%。
- `HUNGER` 配置 10 秒自动扣分和自行车负分缓冲 2，`POINT_LOSS` 配置各级 1／1／2／6／18；非自行车同级追尾也使用此扣分量；自行车同级追尾、自行车及三轮车撞奶牛直接死亡，小汽车及以上奶牛接触扣 2／6／18。`nextHungerAt` 采用有效时间，吃车重置，车型变化不重置，`hungerTick` 每次到期读取 `POINT_LOSS[player.rank]`；同刻接触或弹伤换级先完成，再计算饥饿扣分。自行车总分允许到 −2，低于 −2 才死亡，负分吞吃直接累加；暂停冻结、零速继续，见[成长积分与饥饿](../design/10-成长与饥饿.md)。
- 低级追尾使用 `knockaway` 动画移除目标，不加分、不扣分、不减速；自行车追尾自行车直接死亡；其他同级追尾扣低一级价值、速度减半并移除目标。任何扣分降级使用 `REAR_END_INVINCIBLE_SECONDS` 两秒闪烁保护及 `invincibleUntil` 有效时间截止点。保护忽略车辆、射弹和奶牛，不能吞吃；道路障碍、墙和饥饿继续生效，暂停冻结，到期切分连续事件。饥饿、升级、坑洞减速、泥巴限速、追尾减速和路边刮擦不弹提示，收窄、截止墙、施工封闭、桥梁、河流及铁路均不弹文字提示；场景中的标志保留，缓行及后方来车提示保留。
- `VEHICLE_CONTACT` 配置端面中央宽度比例 0.6、侧面最小纵向重叠比例 0.1 和分离间隙 0.025 米。首次接触面直接区分侧碰与端面，轻微擦角及已有穿透只横向分离。分离目标在当前逻辑步内不重复擦角分离，明确侧碰或中央撞击仍检测，下一步恢复全部检测；不加积分、不降级、不减速、不增加纵向距离、不重置饥饿计时，不提供全局无敌。
- 车身长度采用基础尺寸的 2.4 倍，宽度采用 1.6 倍，自行车再按 `BICYCLE_WIDTH_SCALE` 横向放大 1.53 倍（由原 1.8 倍降低 15% 后取整），碰撞宽度约 1.346 米、长度保持 2.4 米；碰撞与画面共用尺寸。卡车基础长度为 3.75 米，实体长度 9 米，轮轴与货厢随长度配置定位。最宽坦克为 3.00 米，车道宽 3.6 米。一级自行车采用摩托车造型，具有粗轮胎、宽油箱、阶梯座垫、发动机、双侧排气管、短风挡和前后灯，玩家和系统共享模型。路面、路肩和地面分区铺设，镜头近裁面为 0.5 米，减少远处深度抖动；游戏界面禁止文本插入光标与选择。固定一套效果，没有车底色块、随车说明、季节提示或右侧悬浮操作面板。
- `PLAYER_LATERAL_SCALE` 为 1.1，统一增加所有玩家车型横移速度 10%；`Input.advance` 按有效运行时间累计同方向侧移时长，供 `NITRO.eatSideSeconds` 0.4 秒的双倍回气判定，松开、换向、左右抵消或清空按键均重新计时，Z 键不再参与操作。

## 首版边界

桌面键盘操作；无移动触控、回放与存档导入导出。音效由 `src/audio.js` 用 Web Audio 实时合成，不加载音频文件，参数集中在 `config.js` 的 `AUDIO`；环境声按与玩家的距离衰减并带声像，事件声跟随游戏逻辑触发，暂停与结算静音，声音清单与空间模型见[音效系统](../design/12-音效系统.md)。系统车遵守系统间约束，不主动避让玩家。正常生成通过车道和净距约束留下空间，玩家仍需判断实时变道、对向交通及道路关闭风险。

一级车的头盔骑手、圆润油箱及其他静态部件在模型模板中按材质合并，仅两只车轮保持独立，合计十个网格；玩家、系统车和动画残影共用缓存模板及实例批次，泥巴涂层按合并后的部件生成。`BICYCLE_TIRE_WIDTH` 配置缩放前 0.14 米的轮胎宽度；模型及坑洞、泥洞接触共用缩放后的实际宽度。

`TREE_SCENERY` 配置 150 棵实例容量、30% 松树比例、4.8–7.2 米树高和 1.3–1.9 米冠幅缩放。`tree-model.js` 将多簇树冠和三层松针几何各自合并为一个共享模型，顶点明暗随季节底色变化；树干合并分叉枝条。布局按道路种子随机高度、冠幅与旋转，沿用十米静态更新和道路净空检查，仅上传有效实例范围，远行及换局不累计对象。

复杂多车连锁偏移和长时间道路循环仍需在实际游玩中持续观察和调参。当前不引入物理引擎；修改车型尺寸、曲率或最高速度时，需同时检查吞吃判定、并道空间和预警距离。

- 同级有效侧碰由 `classify` 根据实际喷气状态返回 `eat` 或 `bounce`（自行车始终返回 `eat`），回落期间恢复普通碰撞规则。`SIDE_BOUNCE` 配置各车按车宽两倍主弹开及线性减速收尾，总时长 1.5 秒；`startBounce` 设置初始速度，`bounceTravel` 积分横移距离，`advanceBounce` 推进惯性时间，玩家事件切分消费横移，继续检测邻车与障碍；系统车从下一步开始弹开，取消原并道，系统车互相只做横向分离，随后认领最近车道。弹开不加分、不回气、不重置饥饿、不提供保护。自行车同级追尾返回 `bicycleRearFatal`，不经过负分缓冲。

## 随机天气

`WEATHER` 配置普通天气单场 9 秒、秋季横风 6 秒（`windDuration`）、横风 0.5 米/秒及冰冻线性减速 3 秒。`SeasonalWeather` 使用独立种子序列，每 31–45 秒触发一场、任意 60 秒最多两场；天气、车流容量和间距均使用本局有效运行时间，暂停冻结、新局重置。`DistanceFog` 以玩家水平位置为中心，对每个片元按 10–50 米距离平滑增浓，前后共用范围，50 米起完全遮蔽；通过逆相机矩阵还原实例及父节点变换后的坐标，避免把相机深度当作车距。材质只注册一次，雾天切换只更新共享参数，包括原本关闭普通雾的射弹与特效。夏季雷击按火箭防御伤害计算，秋风影响玩家与系统车横移，冬季冰区使车辆减至零并停留 1 秒。天气粒子固定复用；冰冻车身实例仅在实际数量超过当前容量时扩容，适配随时间增长的系统车容量。详细规则见[四季场景](../design/04-四季场景.md)。

## 白马事件

每分钟白马投放、10 秒无敌与 2 秒速度回落均按有效运行时间推进。`Game.collisionStep` 将拾取和强化边界纳入连续事件，无敌期间先撞飞接触目标，不进入普通伤害或吞吃逻辑；饥饿截止点延后 10 秒，氮气保留。静态道路缓存同时校验 `WhiteHorseEvent.revision`，撞破墙体和施工路段当帧隐藏。碎片最多 8 组、每组 6 个，无敌期间系统车仍按原交通规则行驶。详细规则见[白马与无敌冲刺](../design/11-白马事件.md)。

## 防御与速度显示

左侧防御仪表使用当前车型满防御归一化显示百分比，并缓存上次显示值。玩家正常速度上限为 90／110／125／125／125 km/h；对向普通巡航采用基础交通速度乘以 1.44 后按 km/h 四舍五入，环境及碰撞产生的实际速度变化仍连续处理。氮气增幅为 66%，`Nitro.limit` 将各车型喷气上限取整为 149／183／208／208／208 km/h，停喷回落复用同一个取整上限。

## 高架与低沉道路

`Road.structures` 保存高架和低沉事件，使用独立种子序列；`infrastructure` 输出带轮次的稳定事件标识。`elevation` 提供平滑坡道及平坦桥面、谷底，`groundElevation` 保持桥下地面并允许河谷地面降低。道路采样保存独立地面高差，公路条带与地面分开布置。

`RoadInfrastructure` 仅安排高架桥下铁路火车事件，`hasTrain` 按 20% 概率固定，火车随有效运行时间冻结；没有平交道口、信号灯、停止线、铁路制动或火车碰撞路径。河道谷底入口沿用连续接触减半，`dipHits` 保证只触发一次，干燥谷地不限速。

`InfrastructureView` 按材质、投影开关和静态／动态用途区分实例批次。护栏、桥面、桥墩、挡墙、铁路和河道由 `GameRenderer.updateStatic` 每十米重建一次，其余帧共用静态父节点转换；缓存只保留附近结构，新局清空。水纹颜色与六节火车逐帧按有效时间更新，暂停冻结。所有非空批次通过 `addUpdateRange(0, count * 16)` 仅上传有效矩阵范围，空批次隐藏并跳过上传。道路采用蓝灰、青色导向架与金属护栏，主路、副路和高架护栏及立柱均不投射阴影；`InfrastructureView` 按材质和投影开关区分批次，其他独立实例仍保留各自投影设置；路边树木和楼房使用独立地面高度。路段不显示界面文字预告；`UI.roadNotices` 仅对缓行事件使用稳定标识，单次 2.5 秒，暂停不推进。

## 分叉道路

`ROAD_FORKS` 管理分叉投放、880–1760 米路线跨度、800–2000 米副路实际弧长及中段 40–60 米道路边缘空隙、副路坑洞和天气概率；`ROAD_INFRASTRUCTURE.gapMin/gapMax` 为建筑道路之间预留 1600–2320 米空间。`Road` 在地面平坦、车道数稳定且无施工的区间生成分叉，保存两条路径采样及实际弧长；弯曲幅度随机分配，不从曲率推断路线身份。`route` 使用轮次和分叉编号组成稳定标识，主路为 `null`，车辆在入口选择副路后持续沿其中心线移动，至出口回归主路。`pathScale` 将物理速度换算为公共道路里程，累计实际距离作为成绩；`BranchRoadView` 与主路共用配色，静态几何按十米缓存更新，110 个采样点覆盖前后 540 米可视区间。

副路车辆独立投放，运动、避让及系统碰撞与主路统一调度；车身连续碰撞使用路线几何，路面坑洞使用路线内相对横向坐标。副路天气以 85% 概率检查，跨季节随机，天气之间隔 3–7 秒，不受普通每分钟场次限制。白马、特效、雾中心和摄像机均使用当前路线。

`ROAD_DIFFICULTY` 配置 150 秒阶段、60 米前方预留距离、400 米平滑收窄及过渡期子弹增加 10 个百分点。`fourLane` 集中配置后期子弹／火箭加成 25／20 个百分点、随机变道加成 25 个百分点、4–7 秒检查间隔及 25% 危险属性概率。`Road.isFourLanePhase` 以玩家越过永久收窄过渡终点作为统一判断，前期自然四车道不触发；`Road.narrowAfter` 固定一次收窄位置，主、副路同步收窄，不等待分叉结束，后续主副路及跨轮道路永久四车道；`revision` 触发静态几何即时刷新，过滤已取消外侧车道的墙、施工和路面障碍。暂停冻结，新局构造新 `Road` 清空该阶段。

`MANUAL_ACCELERATION` 以车型正常最高速度的 60% 为低速加速门槛，按住上键以每秒 35 km/h 加速，允许零速起步且不消耗氮气；达到门槛后沿用喷气。刹车、刮边和冰冻优先，泥巴及河道仍限制最高速度。


## 热路径与缓存

逻辑保持 120Hz，连续事件仍按接触、保护与饥饿边界切分。`Road.fork`、`route`、基础设施、施工和截止墙共享只读跨轮记录，`ROAD_CACHE.maxLaps` 将道路与障碍缓存分别限制在四轮；收窄阶段清除路线宽度缓存，新局更换道路与车流实例。路线标识在缓存命中后不再拆分字符串。`dip` 与地面高度直接查询种子计划，不创建结构列表；范围查询支持调用方独立持有并复用输出数组，坐标查询支持输出对象，默认调用仍返回独立坐标，避免保留值被后续查询覆盖。

`Game.collisionStep` 在整步开始时查询静态候选，窗口按最高白马速度与全路最小路径比例保留余量，升级和拾取白马后的剩余运动仍在窗口内。远处车辆先剪枝再填写运动快照，事件直接挂目标引用，候选、同刻事件、分离集合和同步扫掠包围盒复用，事件保留独立接触点。`Traffic` 的静态障碍窗口每十米及道路阶段变化时重建，移动奶牛快照逐步同步；危险判断直接读取车辆字段，系统碰撞复用排序列表、运动快照和接触集合。换道安全判断每次读取当前车流，不仅按横向位置缓存。

`Traffic` 每步按起始纵向位置排序并复用避让列表；临近危险只沿行驶方向查询，换道安全查询双向窗口，越过窗口后立即停止。窗口按本车速度、其他车当前及巡航目标的最高速度、双方车长留足余量，覆盖对向来车、减速后恢复及本步已经移动的车辆；汇流口仍检查主副路关联和正在进行的变道。步外查询回退到当前车流，下一步重建列表，新局更换车流实例。天气接触复用独立起止快照，保留步初路线；射弹和建筑原地回收，建筑退出时同步删除冷却，不逐步构造临时集合。

`ROAD_RENDER.sampleCapacity` 将路面采样、各条带顶点及索引的初始容量统一设为 160 点。静态更新前按截止点数量估计最坏采样量，超限时同步扩容并释放旧几何，容量足够时复用缓冲。路边建筑的 1024 容量按形状、材质及动画状态分批计数，当前最多八个区块，即使全为最高层小镇，同一批次最多 800 件。

`DistanceFog` 在场景节点加入时注册子树与材质，绘制仅更新共享参数，动态增加的车型、特效和冰冻实例也走同一入口。坐标转换、闪电向量及车辆／奶牛 ID 集合复用；转向灯与预警灯通过命名引用访问，不依赖子节点顺序。
