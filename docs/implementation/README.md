# 技术与实施说明

[返回总览](../README.md)

## 技术与开发方式

项目采用原生 JavaScript ES Modules、Three.js `0.186.1`、DOM／CSS 界面与 Web Audio 实时合成音效。`package.json` 为 ESM，仅有 `npm start` 启动脚本，没有打包或编译步骤。

入口使用 import map 从 `node_modules` 加载 Three.js。游戏通过 `requestAnimationFrame` 显示和固定逻辑步更新；逻辑、渲染、输入、UI、音频与参数分离。

第一阶段已实现外部场景和驾驶舱预览，支持暂停／继续、失焦暂停和返回外部。飞机状态保持零速度、零油门、发动机关闭、驻车刹车开启；启动、倒数与飞行逻辑尚未实现。

## 本机运行

依赖缺失时 `npm ci`，随后 `npm start`，默认浏览器地址为 [http://localhost:5173](http://localhost:5173)。已有其他服务时用 `PORT=5186 npm start` 指定空闲端口，不停止用户已有服务。

`scripts/serve.mjs` 只监听回环地址，从项目根目录提供 `index.html`、`src/` 和依赖资源；不提供文档和隐藏目录。游戏通过 HTTP 加载 ES Modules，不直接打开 HTML。依赖安装完成后运行资源不依赖 CDN。

项目提供 macOS 启动脚本和 Release 触发的 GitHub Pages 整理工具。当前不发布飞行分支；未来增加资源目录或 Three.js addons 时，静态服务白名单和发布拷贝清单必须同步调整。

## 技术边界

- 保持原生 ES Modules 与本机 HTTP 服务，不引入构建工具或大型框架。
- 飞行逻辑使用简化姿态与动力响应，不引入完整刚体物理引擎。
- UI 使用 DOM／CSS 显示读数与任务，驾驶舱、机场与飞机使用 Three.js 几何。
- 环境声用 Web Audio 合成，英文语音通过本机 Speech Synthesis 管理。
- 渲染共享几何、材质和实例，复用对象与临时向量，按实际测量调整分辨率。
- 输入统一处理焦点、浏览器快捷键、单次按下与持续按住，状态变化由游戏逻辑判断。

## 逻辑与数据契约

完整首版的计划流程为 `READY → INTRO → STARTUP → TAKEOFF_ROLL → INITIAL_CLIMB → COMPLETE → RESULT`，失败直接进入 `RESULT`。`COMPLETE` 只提供最长约 1.5 秒的成功反馈与最后一句播报，随后静音结果页；暂停使用独立标志和恢复阶段，不把暂停重新当作进入阶段执行。

当前预览流程为 `READY → PREVIEW`，空格或按钮直接进入驾驶舱；空格暂停／继续，返回外部重置预览时钟和飞机状态。暂停由独立标志表示，恢复不重复初始化。此预览入口在后续接入倒数和启动流程时调整。

后续飞行逻辑的模块契约：`game.js` 统一推进有效时间，管理暂停和阶段；`aircraft-systems.js` 提供开关就绪状态和合法命令结果；`flight.js` 读取系统状态与输入，更新位置、空速、速度、俯仰、坡度、航向、爬升率和地面接触。渲染和 UI 读取快照，不推进七步任务，不触发起飞或重复播报。

飞机状态包含 `position`、`velocity`、`airspeed`、`pitch`、`bank`、`heading`、`verticalSpeed`、`onGround`、`throttle` 与各系统状态。首版不引入重量字段或机场条件对象；固定推力和升力响应曲线决定体验。

采用 Three.js 的 Y 轴向上约定，以地面 XZ 平面表达跑道与航向。机体中心／参考点、轮胎触地点、相机眼位与仪表台位置统一定义；AGL 由最低接触点和地面高度推导，不因相机高度发生变化。内部采用米／秒／弧度，显示层统一转成 kt、km/h 和角度。

地面使用轮子约束与随速减弱的转向；空中使用简化姿态、升力、推力和阻力响应，不加入完整刚体物理引擎。起落架与襟翼的逻辑进度同时驱动外观和飞行效果。离地不重置位置或突然切换速度，VR、低速和成功条件只在逻辑层判定。

完整首版计划通过 `event.code` 使用物理按键：`KeyL`、`KeyD`、`KeyH`、`KeyA`、`KeyF`、`KeyW`、`KeyR`、`KeyT`、`KeyS`、`KeyG` 与方向键、空格。忽略编辑输入和浏览器组合快捷键；开关过滤 `event.repeat`，持续按键从按下集合读取。暂停、失焦和阶段输入切换时清理集合，恢复不沿用旧的按住动作。

键位学习是产品约束。操作表统一定义物理键码、键帽、英文助记词和中文动作，UI 与输入共用这张表，避免“提示的键”和“实际监听的键”不同。未来标点使用 `Comma`、`Period`、`Semicolon`，不能比较 `event.key` 输出的全角标点；明确区分物理位置与输入字符。当前只记录规划，不添加尚未使用的标点监听。

## 时间、事件与声音

当前采用 120 Hz 固定逻辑步推进预览时钟；静止场景仅在视角、尺寸或连接状态改变时重绘。外部待机与暂停停止持续帧调度，恢复重置显示时间基准，不补算暂停时长。后续接入连续飞行画面时再增加显示插值。倒数、启动、收放和成功保持计时均使用有效游戏时间。暂停冻结，恢复不补算停留时间；不通过多个 `setTimeout` 驱动玩法。

使用本局编号与稳定步骤／状态事件 ID 防重：开关完成、发动机就绪、VR、离地、收放、警告进入、成功／失败。速度和高度的逐帧变化不是新事件。提示持续时间最多 3 秒，常驻任务独立渲染；声音只能消费有效事件，不能在 UI 更新中播放。

Speech Synthesis 的音量与队列不属于 Web Audio 图，暂停时必须同时取消原生语音和合成声。检测不到合适的本机女声时明确降级，不能报告“女声已完成”。具体播报表见[声音与引导](../design/05-声音与引导.md)。

## 渲染与后续扩展

当前双窗共用场景和相机，窗框与仪表台采用相对眼位的几何，外部客机在内舱视角隐藏以防遮挡。主相机读取机体眼位与姿态；相机轨迹与连续衔接将在第二阶段实现。共享几何材质，复用对象与临时向量；机场范围有限，先保证外观、遮挡和操作可读，再按实际测量优化。

进入远距离巡航后再启用玩家附近相对坐标与地形区块回收，逻辑位置保持连续。未来天气影响飞行环境，路面类型只作用于地面摩擦／滚阻；二者分别配置，不要求新增重量、载重或机场性能模型。

首版不提供存档；未来如保存飞行设置或记录，使用明确的命名空间与版本。发布与资源目录变更在实际开发时处理。
