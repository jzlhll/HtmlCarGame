# 技术与实施说明

[返回总览](../README.md)

## 技术与开发方式

项目采用原生 JavaScript ES Modules、Three.js `0.186.1`、DOM／CSS 界面；声音规划采用 Web Audio 实时合成。`package.json` 为 ESM，仅有 `npm start` 启动脚本，没有打包或编译步骤。

入口使用 import map 从 `node_modules` 加载 Three.js。游戏通过 `requestAnimationFrame` 显示和固定逻辑步更新；逻辑、渲染、输入、UI、音频与参数分离。

已实现外部场景、四秒倒数运镜、五项自由准备、三秒点火、条件放行、地面滑跑、离地爬升、条件收轮收襟翼及结果页。支持暂停／继续、失焦暂停和重开。另已实现静态山河城市、地标、机外姿态卡片和基于迎角的失速与安全警告。声音与天空巡航尚未实现。

## 本机运行

依赖缺失时 `npm ci`，随后 `npm start`，默认浏览器地址为 [http://localhost:5186](http://localhost:5186)。已有其他服务时用 `PORT=5187 npm start` 指定空闲端口，不停止用户已有服务。

`scripts/serve.mjs` 只监听回环地址，从项目根目录提供 `index.html`、`src/` 和依赖资源；不提供文档和隐藏目录。游戏通过 HTTP 加载 ES Modules，不直接打开 HTML。依赖安装完成后运行资源不依赖 CDN。

项目提供 macOS 启动脚本和 Release 触发的 GitHub Pages 整理工具。当前不发布飞行分支；未来增加资源目录或 Three.js addons 时，静态服务白名单和发布拷贝清单必须同步调整。

## 技术边界

- 保持原生 ES Modules 与本机 HTTP 服务，不引入构建工具或大型框架。
- 飞行逻辑以固定质量进行三维受力积分，姿态采用限速控制；不引入完整刚体力矩引擎。
- UI 使用 DOM／CSS 显示读数与任务，驾驶舱、机场与飞机使用 Three.js 几何。
- 环境声用 Web Audio 合成，英文语音通过本机 Speech Synthesis 管理。
- 渲染共享几何、材质和实例，复用对象与临时向量，按实际测量调整分辨率。
- 输入统一处理焦点、浏览器快捷键、单次按下与持续按住，状态变化由游戏逻辑判断。

## 逻辑与数据契约

当前流程为 `READY → INTRO → STARTUP → TAKEOFF_ROLL → INITIAL_CLIMB → COMPLETE → RESULT`，失败直接进入 `RESULT`。空格或按钮开始四秒倒数，结束时仍熄火。五项全部就绪才能 F；发动机运行且零油门才能 R。静止零油门时准备开关可反向关闭并恢复驻车；运动中 D／H／R 禁止，L／A／F 不自动驻车。R 后开始接收飞行输入，离地由飞行逻辑判定；G／W 检查安全条件后连续收起。成功条件连续满足 3 秒后冻结飞机，`COMPLETE` 显示 1.5 秒反馈，随后进入静止结果页。失败只结算一次。

暂停采用独立标志，冻结逻辑、发动机、提示和成功计时；重开清空本局状态与事件。进入准备、放行、完成／结果和暂停切换时清空按住集合；滑跑到爬升保留持续操纵，避免离地中断油门与俯仰。普通开关变化和失败输入不清空逻辑步余量。

模块契约：`game.js` 统一推进有效时间，管理暂停和阶段；`aircraft-systems.js` 提供开关就绪状态和合法命令结果；`flight.js` 读取系统状态与输入，更新位置、空速、速度、俯仰、坡度、航向、爬升率和地面接触。渲染和 UI 读取快照，不推进七步任务，不触发起飞或重复播报。

飞机状态包含 `position`、`velocity`、`airspeed`、`pitch`、`bank`、`heading`、`verticalSpeed`、`onGround`、`throttle` 与各系统状态。另含 `enginePower`、`angleOfAttack`、`flightPathAngle`、`loadFactor`、`lift`、`drag`、`thrust`。质量固定于 `AERODYNAMICS.mass`，不设可变载重字段或机场条件对象；气动参数和安全阈值统一定义于 `config.js`。

采用 Three.js 的 Y 轴向上约定，以地面 XZ 平面表达跑道与航向。机体中心／参考点、轮胎触地点、相机眼位与仪表台位置统一定义；AGL 由最低接触点和地面高度推导，不因相机高度发生变化。内部采用米／秒／弧度，显示层统一转成 kt、km/h 和角度。

地面通过重力、升力与推力向上分量求轮子支撑和可用摩擦，转向受轮胎抓地力限制；空中按速度方向计算阻力、垂直气流并随坡度转向的升力、机头方向的推力和重力，积分三维速度。迎角由俯仰减航迹角得到，越过临界迎角后升力连续衰减、阻力上升；恢复需减小迎角并保持安全区。发动机有推力响应延迟，操纵效率随动压降低，姿态变化率受限；不直接追随目标高度或垂直速度，不加入完整刚体力矩引擎。起落架与襟翼的逻辑进度同时驱动外观和飞行效果。离地不重置位置或突然切换速度，VR、低速和成功条件只在逻辑层判定。

通过 `event.code` 使用物理按键：`KeyL`、`KeyD`、`KeyH`、`KeyA`、`KeyF`、`KeyW`、`KeyR`、`KeyT`、`KeyS`、`KeyG` 与方向键、空格。不区分字母大小写，允许 Shift＋字母，Caps Lock 不改变命令；忽略编辑输入与 Ctrl／Alt／Meta 快捷键，其他 Shift 组合保持忽略。开关过滤 `event.repeat`，持续按键从按下集合读取。T／S 每次新按下先调节 5%，持续输入每秒调节 28%，S 优先；↑／↓ 每次调目标 1°，持续每秒 3°，实际姿态限制变化率。左右转向只按持续集合处理。暂停、失焦和阶段输入切换时清理集合，恢复不沿用旧的按住动作。

键位学习是产品约束。操作表统一定义物理键码、键帽、英文助记词和中文动作，UI 与输入共用这张表，避免“提示的键”和“实际监听的键”不同。未来标点使用 `Comma`、`Period`、`Semicolon`，不能比较 `event.key` 输出的全角标点；明确区分物理位置与输入字符。当前只记录规划，不添加尚未使用的标点监听。

## 时间、事件与声音

当前采用 120 Hz 固定逻辑步推进有效时钟和倒数，四个数字各占一秒。开场每帧按有效进度重绘；熄火状态按需重绘，发动机启动和怠速期间持续重绘以表现微振。UI 按系统状态、百分比或提示变化更新，不逐帧重复构建仪表和清单。帧内阶段切换不额外调度第二个帧循环。外部待机与暂停停止持续帧调度，恢复重置显示时间基准，不补算暂停时长。开场相机使用逻辑步剩余时间采样连续显示进度，暂停保留最后显示位置；滑跑与爬升从相邻逻辑快照插值，机体和相机共用显示姿态，暂停与结果保留最后显示姿态。倒数、启动、收放和成功保持计时均使用有效游戏时间。暂停冻结，恢复不补算停留时间；不通过多个 `setTimeout` 驱动玩法。

入舱说明的隐藏状态由 `Game.startupHintDismissed` 保存；输入层通过 `onActivity` 通知首次普通字母或已映射操作按下，暂停与倒数阶段不消耗说明，Ctrl／Alt／Meta 快捷键与连发忽略。UI 只显示一次概括说明，不逐步推荐单项；条件失败提示独立保留，重开恢复说明。

当前系统通过 `Game.onEvent` 发出 prepared、unprepared、engine-start、engine-stop、engine-ready、released、brake-set 和 blocked 事件；飞行补充 rotation-ready、liftoff、gear-start／gear-up、flaps-start／flaps-up、low-speed、pitch-high、pitch-low、overspeed、stall、stall-recovered、complete、failed 事件，包含本局编号、事件轮次、事件类型、操作键与条件标识。每次实际开关切换或发动机就绪推进一次轮次，字母命令统一为大写标识；长按连发不产生切换事件。blocked 在同一轮次按操作键与缺失条件组合去重，到期后也不重复提示；有效状态变化后进入新轮次，允许同一操作重新确认。后续使用本局编号与稳定步骤／状态事件 ID 防重：开关完成、发动机就绪、VR、离地、收放、警告进入、成功／失败。速度和高度的逐帧变化不是新事件。警告使用进入阈值和恢复阈值去抖，安全区保持后才允许下一轮进入；失速提示优先于仰角／危险下降，后者优先于低速／超速和操作受阻。负迎角失速提示抬高机头，正迎角失速提示降低机头，均以减小迎角绝对值为目标。临时提示最多 2.5 秒，操纵按键不清除安全提示；超时后底部危险指引与仪表状态仍保留。常驻任务独立渲染；声音只能消费有效事件，不能在 UI 更新中播放。

Speech Synthesis 的音量与队列不属于 Web Audio 图，暂停时必须同时取消原生语音和合成声。检测不到合适的本机女声时明确降级，不能报告“女声已完成”。具体播报表见[声音与引导](../design/05-声音与引导.md)。

## 渲染与后续扩展

当前双窗共用场景和相机，窗框与仪表台采用相对眼位的几何，外部客机在内舱视角隐藏以防遮挡。主相机读取机体眼位与姿态，并向下偏转 5°以保留爬升中的地景；机外卡片使用相同显示姿态，同一渲染器通过裁剪视口绘制独立场景，不改变主相机或新增 WebGL 上下文。开场相机以驾驶舱眼位为中心，用单调极角与递减半径生成沿飞机左侧的收拢轨迹；位置、高度、水平朝向、俯仰与视野角共用平滑有效进度，避免分段朝向反转，首尾减速并对齐外部待机和驾驶舱眼位；外部模型在接近机壳前淡出，内舱几何平滑出现。时长、外部起点与淡入淡出区间集中在 `CAMERA`，终点读取 `AIRCRAFT.eye`。点火振动从系统有效时间采样确定性波形，启动时平滑进入并减弱为怠速微振；参数集中于 `ENGINE_VIBRATION`，只改变相机眼位和微小角度，不改变机体逻辑姿态，暂停重绘不产生随机跳动。外部近裁剪面为 1 米，进入驾驶舱时平滑调整到 0.25 米，参数集中于 `CAMERA`。地表材质按 `SCENERY.surfaceLayers` 设置 polygonOffset，使地面、道肩、跑道与标线的深度顺序稳定。外机与内舱材质保持不透明渲染队列和深度写入，多采样可用时以 alphaToCoverage 控制淡入淡出，否则使用 alphaHash；仅修改 opacity，不在过渡中切换材质透明模式或反复编译。阴影缓存只在可见机体变换、收放状态、机壳透明度改变或 WebGL 恢复时失效，内舱飞行不因隐藏外机的位置变化重算；镜头移动不重算静止场景阴影。开场取消顶部状态条的背景模糊，降低运动画面的合成开销。共享几何材质，复用对象与临时向量；机场范围有限，先保证外观、遮挡和操作可读，再按实际测量优化。

静态地景的城市场景与山体合并几何或实例化；天空半径、远裁剪和雾范围覆盖地景，采用对数深度减少远近范围扩展后的交错。当前地景是视觉背景，接地仍以机场平地判定，建筑／山体碰撞待独立设计。进入远距离巡航后再启用玩家附近相对坐标与地形区块回收，逻辑位置保持连续。未来天气影响飞行环境，路面类型只作用于地面摩擦／滚阻；二者分别配置，不要求新增重量、载重或机场性能模型。

首版不提供存档；未来如保存飞行设置或记录，使用明确的命名空间与版本。发布与资源目录变更在实际开发时处理。
