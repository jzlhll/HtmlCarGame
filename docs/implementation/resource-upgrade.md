# 版本与资源升级

[返回实现说明](README.md)

## 版本依据

`src/version.js` 的 `APP_VERSION` 是程序版本与下一次正式发布 tag 的唯一依据，当前为 `v1.0.9`，对应最新已发布 `v1.0.8` 的下一补丁版本。发布时直接使用常量作为 tag；发布后开启下一轮开发再递增，启动、刷新和同一轮日常修改不递增。`package.json`、锁文件及根包版本使用相同数字，不带 `v`。Pages 整理校验这些字段和所发布 tag 一致，不一致即停止。

`GENERATOR_VERSION` 表示生成算法兼容版本，`CACHE_FORMAT_VERSION` 表示持久数据格式，均独立于程序版本。只改玩法、文字或程序 tag，不应无条件丢弃仍兼容的生成资源。

## 资源与指纹

`scripts/resource-sources.mjs` 按源码依赖生成指纹，本机服务动态提供 `src/resource-sources.js`，Pages 整理时写入发布目录；生成清单已忽略，不进入 Git。`resource-plan.js` 将源码、任务、模型相关配置、Three.js 版本、固定种子与缓存格式组合成资源键。目前分为十四种像素、车辆与动物、X 路障、树木、岩石、恐龙、灾害二十组。恐龙显式依赖车辆共享几何，模型依赖改变须同步维护资源组。

IndexedDB `htmlCarGame.models.v1` 保存可转移的顶点属性、索引与像素数组；材质、GPU 纹理和场景对象在当前页面重新创建。恢复前校验结构、类型、数量、索引、有限数值和别名依赖；缺失或损坏时仅重建对应组。组内任务可逐个让出执行，刷新命中不再生成，同页重开继续复用内存。

## 启动与升级顺序

1. 轻量入口先检查最后一次成功记录。无有效版本记录显示“首次准备”；版本或资源键改变显示“版本升级”及进度。准备完成前不开放开始。
2. 优先恢复兼容资源，其余通过模块 Worker 分批生成；Worker 不可用时按相同算法协作式回退。全部关卡资源在非游玩阶段准备，进入游戏前停止 Worker，驾驶期间不生成。
3. 校验并逐组写入新结果，成功后才清理旧生成缓存，再提交 `successful-version` 记录。单纯版本号改变可复用全部资源。
4. 最后组装游戏并预热本关 GPU 资源，完成首次绘制后允许开始。模型和纹理不以预制文件加入仓库。

支持 Web Locks 时，同源页面以 `htmlCarGame:model-upgrade` 锁串行准备；清理前再读成功记录，旧页面不能覆盖更高的版本记录或清理其资源。Pages 所有运行模块、Worker、引擎与样式地址均带程序版本查询参数，防止新旧模块被 HTTP 缓存混用。

## 清理、失败与降级

清理范围仅限当前资源库中过时键，以及以 `htmlCarGame.model(s)`、`assets`、`generated` 或 `cache` 为命名空间的本游戏旧 IndexedDB、Cache Storage 和 localStorage 生成缓存，包含无版本记录；不扫描或删除其他项目数据。成绩 `htmlCarGame.save.v1`、涂装 `htmlCarGame.color.v1`、儿童模式 `htmlCarGame.childMode.v1` 保留。

准备、校验或清理失败不提交成功记录，保留已写入的可用资源，显示重试入口。重试复用已完成结果；旧页面占用数据库时提示关闭后重试。持久存储不可用或配额不足时明确提示仅为本次页面准备，允许使用内存资源，但不登记持久升级成功；下次刷新仍需核对。

## 验证口径

导航目标不超过六秒，计入加载、恢复或生成、世界组装、GPU 预热与首个可开始画面；全部发布文件小于 10,000,000 字节。性能日志通过 `MODEL_APPEARANCE.profile=1` 启用。验证首次生成、同版刷新、仅版本改变、单组损坏、无版本遗留清理、失败重试、不可持久化降级，以及成绩／偏好和其他项目数据保留；临时检查入口不进入发布目录。
