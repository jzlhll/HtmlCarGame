# 技术架构与存档

## 工程边界

独立网页工程使用 JavaScript ES Module 和 `three@0.186.1`，本工程维护 `package.json` 和 `package-lock.json`。

引擎由本工程独立安装和打包，不通过 CDN 临时加载，不依赖其他游戏的 `node_modules` 路径或启动服务。资源使用相对路径，兼容静态部署子路径；开发服务与静态打包脚本均由本工程维护。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| 玩法配置 | 方块占用格、模式集合、经典七档速度、无尽提速曲线及已确认参数 |
| 规则状态 | 棋盘、活动方块、碰撞、旋转、落地、bonus 穿透与整行消除、结束判定 |
| 残局生成 | 依据初始高度、种子和配置，在新局生成初始棋盘并检查约束 |
| Three.js 视图 | 将规则状态映射到方块、落点预览和视觉反馈 |
| 输入与界面 | 键盘、触屏、开始、暂停、继续、模式与档位选择 |
| 存档 | 快照序列化、同步写入、校验、恢复及存储错误反馈 |

上述为职责边界，不强制一项一个文件。玩法层不依赖 WebGL，视图层不重复维护一份规则棋盘。即使采用立体外观，碰撞仍按整数网格计算。

## 状态与计时

建议使用 `ready`、`playing`、`paused`、`gameOver`、`completed` 表示主要状态，`completed` 仅表示经典模式完成第七关后的通关结果；残局模式没有过关或通关状态，正常游玩直到失败进入 `gameOver`。

- 所有入口复用统一状态转换，不让按钮、键盘和生命周期事件各自修改计时器。
- 下落与锁定基于有效游玩时间，不能按渲染帧计数。恢复时重设时钟基准，不把后台经过的时间补算为下落。
- 经典模式以当前关卡有效游玩时间推进，每关 120 秒，关卡与速度一一对应。升级只更新关卡、速度和本关计时，保留棋盘、活动方块及队列；第七关完成后进入 `completed`，停止下落、输入移动和计时。
- 残局模式每累计有效游玩 150 秒，按玩法文档的速度曲线提速一次，不用关卡驱动残局重建。保存当前速度和本次提速周期的已用时间，恢复后不能降速、重新计满 150 秒或补算后台时间。
- 残局模式的 `bonus` 使用同一有效游玩时钟，按玩法文档随机间隔调度；到期仅标记一个待发放奖励，下次出块时优先发放，之后重新抽取间隔。暂停、恢复、提速和队列预览不得额外抽取或重复发放。
- `bonus` 的逻辑占用为一格，左右移动和向下穿透均忽略堆叠阻挡，但保留棋盘边界检查。落点按当前列可停留的最深空位计算，不复用普通方块遇到紧邻占用格就锁定的判定；消除所在行通过统一消行事务更新棋盘和统计，不参与过关判定。
- 暂停先停止规则推进并清除按住的输入，再从一致状态取得快照。
- 同步的移动、落地和消行事务完成后才接受暂停快照，避免保存半次消行。
- 不为这些同步操作额外引入 revision 或 generation 状态；若后续存在异步准备，优先复用任务取消、等待和状态校验。

## 渲染与资源

- 棋盘、方块几何与共享材质在准备阶段创建；游玩时只更新已有对象的变换、颜色和可见性。
- 方块按共享几何、材质或实例池复用，重开和恢复不重新生成整套资源。
- 棋盘大小改变前，按准备阶段预算扩充容量；不能在活动游戏循环中生成几何或纹理。
- 暂停和静止画面按需绘制。容器尺寸变化同步调整绘制尺寸和相机，避免逐帧读取布局。
- 活动 `bonus` 通过已有对象的可见性或材质参数持续闪烁，不生成额外几何或纹理；闪烁不影响碰撞和消行判定，暂停时冻结视觉动画。
- 简单几何的 GPU 对象保留在会话内复用；这类引擎对象不直接写入存档。若引入昂贵的程序资源，应另外设计版本化持久缓存。
- 玩家存档与生成资源缓存分开命名和维护。程序更新、资源清理不得直接删除本局进度。

## 存档内容

使用小体积 JSON 快照，优先通过 `localStorage` 的单键同步写入保存。每种模式一个独立键，命名须包含本工程前缀；存档包含格式版本，与程序版本分开。

| 内容 | 要求 |
| --- | --- |
| 身份与格式 | 格式版本、模式、玩法状态、保存时间，不能用时间戳驱动恢复后的玩法 |
| 棋盘 | 宽高、全部已落地格子的占用与方块类别 |
| 活动方块 | 形状标识、旋转状态、位置 |
| 后续方块 | 完整已抽取队列，以及抽取算法需要的袋／随机状态 |
| bonus | 本次已抽取间隔的剩余有效时间、是否待发放及调度所需随机状态；活动中的 bonus 由活动方块字段保存 |
| 速度 | 初始档位、当前实际速度、下落进度；残局模式另含提速进度及速度曲线需要的状态 |
| 经典关卡 | 当前关卡及本关已用时间，仅用于经典模式 |
| 无尽进度 | 累计有效生存时间，仅用于残局模式，不包含过关或剩余初始残局目标 |
| 计分 | 得分、累计消行等已确定的统计 |
| 计时 | 下落累计时间、锁定剩余时间等影响下一步行为的数据 |

存档以当前棋盘为恢复依据，初始残局消除后继续正常游玩；不为过关判定额外保存初始残局副本或追踪原始格子的身份。若保留生成种子，只作为复现信息，恢复时不能重新生成棋盘替代当前局面。

## 保存入口

1. `playing` 进入 `paused` 时立即同步保存，保存成功后更新界面提示。
2. `blur`、`visibilitychange` 进入隐藏和 `pagehide` 触发相同入口。连续触发必须幂等，不重复推进玩法。
3. 切换模式前暂停并保存当前模式，目标模式从独立存档或准备界面进入。
4. 页面刷新后读取本模式存档，未完成局显示继续入口，恢复状态为 `paused`，由玩家主动开始计时。若保存的是 `completed`，还原通关结果和最终堆叠，不能转成 `paused` 后继续下落。

浏览器或系统强制终止进程不保证触发生命周期事件，因此不能承诺所有异常退出均有最新进度。是否增加落地、提速或经典模式过关检查点，由后续实现范围决定；手动暂停保存是必需行为。

## 校验与失败处理

- 读取时捕获存储访问和 JSON 解析异常；校验格式、模式、棋盘尺寸、数组长度、格值、方块形状、旋转、坐标、数值范围及活动方块放置合法性。
- `bonus` 穿透中的活动状态使用专门的合法性校验，不能因其与堆叠暂时重叠就按普通方块判为损坏；合法落点仍必须为空。校验剩余间隔和待发放状态的一致性，不能因读档补发多次奖励。
- 格式不兼容或损坏时不直接参与玩法，不静默覆盖；展示无法继续原因并允许明确选择新局。
- 对旧版本只执行有定义且可验证的迁移；迁移失败保留原数据。
- 存储禁用、容量不足或写入失败时，保留内存中的本局状态，提示保存失败并允许重试。
- 写入失败不展示成功时间，不自动清空此前有效快照。只在明确开始新局或确认不再需要该局后替换相应模式的存档。
- 保存只修改本工程的键，不调用 `localStorage.clear()`，不影响其他游戏。

## 实际文件入口

- `src/config.js`：版本、尺寸、方块朝向、速度间隔和时间常量。
- `src/game.js`：纯规则 `Game`，含确定性随机流、洗牌袋、残局生成、消行、计时和 bonus。
- `src/storage.js`：两模式独立存档与设置，校验格式、棋盘、活动方块和队列；保存保留随机状态和未发放 bonus。
- `src/scene.js`：`BoardView`，准备时创建实例池、星形几何和材质并预热；游戏中复用实例矩阵、颜色和可见性。
- `src/main.js`：输入、界面、音效、生命周期、准备完成版本记录及状态协调。
- `scripts/serve.mjs`：仅监听本机的静态开发服务，默认端口 5177。
- `scripts/prepare-pages.mjs`：将源码与必要引擎文件整理至忽略的 `.pages-output/`，统计原始和 gzip 字节，并限制原始体积不超过 10 MB。

输入与计时在 rAF 中按不超过 16 毫秒的小步推进；显示中断超过 1.5 秒时自动暂停，避免一次恢复推进大量方块。普通暂停同步写入存档，并在落地、提速、结束时增加保存检查点。无进行中的动画和玩法时取消 rAF，画面按需绘制。

音效通过 Web Audio 合成，不下载音频文件。画面不使用图片或程序纹理，所有几何仅为小型方块和一颗星。GPU 对象采用会话内复用，不建立 IndexedDB 几何缓存：直接恢复这几个小型内建几何和矩阵池比增加序列化、数据库读取及迁移路径更简单；跨页面仍需重新创建 WebGL 对象，不能宣称持久资源缓存命中。

页面在 Three.js 编译和首次绘制成功后才记录成功程序版本；不同版本启动显示“版本升级”，存储不可用时只完成本会话准备，不改动玩家存档或清理其他游戏数据。
