# 开发与验证效率

操作以[常规验证流程](validation.md)为准；本文保留效率原则及待验证建议，避免重复维护步骤。

## 已明确的原则

| 原则 | 执行方式 |
| --- | --- |
| 投入匹配风险 | 碰撞、路线和时序核对交叉边界，局部改动只检查受影响结果 |
| 复用有效信息 | 批量独立查询，依赖查询顺序展开；仅新增改动、失败或疑点触发重查 |
| 先测量后优化 | 用小样本确认热点和收益，不凭调用频率或算法复杂度决定；正确性和容量保护按实际风险处理 |
| 集中预览 | 先定位逻辑边界，再统一刷新确认画面；服务或标签故障先查原因，不盲目重试 |
| 清楚报告进展 | 说明当前结论、待解疑点和证据范围，必要检查完成即结束 |
| 复用音效能力 | 用 `audio.js` 的 `tone`、`burst` 和循环声，数值进 `AUDIO`；试听可临时放宽场景触发条件，结束还原 |

## 待验证建议

以下建议不作为默认要求，确认收益后再纳入上述原则。

- 重复边界可复用固定种子和少量场景参数；先评估覆盖与维护成本，不主动增加持久测试或调试入口。
- 少量任务记录核对、修改及验证耗时，用数据定位成本；记录应足够轻，不设主观时间上限。
- 先选代表性小样本，出现差异再扩大；碰撞和时序仍须明确边界，不能只靠随机种子。
- 模型先预览轮廓、尺寸及可见性，再完善材质、动画和合批；收益应扣除额外预览及临时模型成本。
