# 版本与资源升级

[返回实现入口](README.md)

## 版本与指纹

`src/version.js` 的 `APP_VERSION` 是程序版本和正式发布 tag 的唯一依据，当前 `v1.0.9`，包与锁文件使用 `1.0.9`。同轮修改、启动、刷新不自动加版本，不创建发布 tag。`GENERATOR_VERSION` 与 `CACHE_FORMAT_VERSION` 均为 8，分别只在生成算法兼容性和持久格式变化时递增；运行调度或画质调参不使兼容资源失效。

`scripts/resource-sources.mjs` 为生成算法依赖建立指纹；本机服务动态提供 `src/resource-sources.js`，发布整理写入静态包，清单不提交 Git。资源库为 `english-air-combat-assets`，保存三类资源及完成记录：

| 资源组 | 键的依据 | 持久内容 |
| --- | --- | --- |
| 星空／飞机／航母 | 生成源码、Three.js 版本、种子、生成参数与格式 | TypedArray 几何、球体索引、纹理像素、星点与布局 |
| Boss | 独立源码指纹、格式与造型参数 | 两套主体和触手的顶点色几何 |
| 幸运箱 | SVG、尺寸、DPR 和阴影配方 | PNG 数据 URL，恢复后解码共享图片 |

速度、蒙版、画质与菜单帧率不进入几何／像素指纹。同格式兼容的旧完整配置键可读取后登记新键。GPU 对象不持久化，缓存命中只恢复底层数据并构造场景，不重新生成几何和像素。

## 准备与预热

入口预加载 Three.js 两个引擎模块，场景模块导入与资源准备并行。打开数据库并读取完成记录后，三条资源链并发恢复或生成；各自校验并写入，进度只向前推进。无 Worker 时使用相同分批生成器让出主线程。

必须等待全部任务完成或停止，才关闭数据库、展示失败或继续组装。任一必要资源失败时不提前返回而遗留其他 Worker。场景创建后在非游玩阶段预热全部几何、纹理和材质变体，完成后才开放操作；游玩及同页重开复用资源。

## 成功、失败与数据隔离

全部必要资源验证成功且持久写入完成后，才在同一事务清理本游戏过时生成键并写入 `meta:completed`。清理前核对程序版本，旧页面不能清理或覆盖更高程序版本的成功记录。独立资源组继续复用，禁止因程序版本或运行调度变化删除全部生成缓存。

数据库不可用或写入失败时明确提示仅本页内存可用，不登记持久升级成功；保留旧完成记录和可用资源。幸运箱位图失败可使用原 SVG 降级。学习、成绩、账号、关卡、复习及其他游戏的数据不在生成缓存清理范围内。

验证首次、命中、单组改变、损坏、失败等待和无持久存储路径，分别记录资源、导入、构造、预热与模块启动至就绪耗时。准备目标不超过 6 秒，静态包小于 10 MB；现行实测与边界见 [英语空战验收](english-air-combat-validation.md)。
